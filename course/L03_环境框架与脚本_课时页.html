2平台配方法：开通哪家，上面跑什么

结论1.7B 加 QLoRA 这个量级，三家都跑得动，差的不是算力，是「开通要多久」和「上去装什么」。先开免费那家，今天就能出第一个 loss；按量那家当备胎，只充最小额度。

先说清楚一件事：平台之间不是替代关系，是分工。同一份脚本换个平台跑，改的只是路径和模型来源，方法本身不变——但每家预装了什么、绑定了哪个框架，决定了你上去该顺着哪条路走。

一张表看完：去哪家、跑什么方法、装什么

主线一句话：方法不变，只换谁来跑——AutoDL 上交给 LLaMA-Factory，魔搭上交给 ms-swift，两家都不手写脚本。卡型、价格、免费额度随时在变，开户前看平台当下的实时页；这张表锁的是方法搭配，不锁价格。

为什么是这三个搭配

不是「哪家好」，是「这家给什么，就顺着用什么」
魔搭
配 ms-swift。模型库、Notebook、训练框架是一家出的，模型走内网下，不用等公网；Qwen3-1.7B 站内直接可下。QLoRA 4bit 下基座只占 0.9G，24G 的 A10 松得很，批大小（batch）敢开大。代价：单次有时长上限，训练必须开 save_steps，被停了能接上。
AutoDL
配 LLaMA-Factory，单卡再叠 Unsloth。它卖的是裸机器加镜像市场，LLaMA-Factory 的镜像现成摆着，开机就能训，省掉自己装框架那两小时；模型小、还想再快一档，就在同一个环境里加 Unsloth 加速。代价：系统盘关机就清，路径写错一次就要重传数据；镜像要挑新版，老镜像里的框架跑不动新模型。
本地
只做轻活。改脚本、拼数据、跑几条推理，这些不用排队等卡。真要在这儿训练，先看显存：8G 以下别试 1.7B 的 QLoRA，勉强够了也慢到没有意义。代价：Windows 上 bitsandbytes 装不上是常态，装不动就换 WSL，别修三天。

3三个入口：谁替你写训练循环

结论LLaMA-Factory 和 ms-swift 是「框架」，替你写完从读数据到存 adapter 的全流程；Unsloth 是「加速内核」，只替换底层算子。前者管流程，后者管速度，两者可以叠。
入口装什么装完怎么验什么情况选它
LLaMA-Factory仓库 + pip install -e ".[torch,metrics]"llamafactory-cli version 有输出，webui 能打开想最快看到第一个 loss；要给不写代码的人演示
ms-swiftpip install ms-swift -Uswift --help 有输出国内网络、用魔搭的模型和免费算力
手写 + peft只需要那四个核心包能 import，get_peft_model 后打印出可训参数非主线：要改数据拼装、改 loss，或想看清每一步时才用
Unslothpip install unsloth能 FastLanguageModel.from_pretrained单卡、显存吃紧、模型在它支持列表里；只认 Linux

一个框架一个环境，具体怎么做

# 三个入口各占一个环境，互不干扰
conda create -n lf python=3.10 -y && conda activate lf
pip install -e ".[torch,metrics]"        # 在 LLaMA-Factory 目录里

conda create -n swift python=3.10 -y && conda activate swift
pip install ms-swift -U

conda create -n hand python=3.10 -y && conda activate hand
pip install torch transformers peft trl bitsandbytes datasets accelerate

# 每个环境装完，都跑一遍那三行验证，再 freeze 出锁文件
pip freeze > requirements.lock.txt
怎么选本课主线是 LLaMA-Factory：配置驱动、镜像现成、有 WebUI 能演示。什么时候换：国内网络下模型下不动，换 ms-swift；单卡要再快一档、模型在支持列表里，叠 Unsloth；要改数据拼装或改 loss，才退回去手写那三十行。
别把三套命令混着记。它们参数名很像但不完全一样：数据一个要注册数据集名、一个直接给路径。真正要记住的只有一件事：数据字段怎么映射。换框架时八成报错都出在这。
这一章钉住了三件事
  • 钉住了：框架管流程、内核管速度，两者不在一个维度，可以叠着用
  • 不这么做会：把三个名字当三选一的竞品各学一遍，底层还是没懂，报错还是查不出
  • 下次遇到同类问题，先问：我是要省事，还是要提速，还是要看清每一步
带走框架是主线，手写是参照——看得懂底层那三十行，报错才知道往哪查。

4模型准备：下载、验模板、量长度、算显存

结论权重下下来不算准备完。四件事做完才算：文件齐、模板能套、长度量过、显存算过。少做一件，训练时就会以「效果不对」的形式报出来。
步骤做什么怎么算过
① 下载权重 + tokenizer + config 下到数据盘；国内走魔搭或镜像站目录里文件数与模型卡一致，config.json 能解析
② 验模板用 apply_chat_template 拼一条，repr() 打出来看角色标记、特殊 token、结尾符和基座训练时一致
③ 量长度把训练集全过一遍 tokenizer，统计 50 / 95 / 99 分位拿到三个数，cutoff_len 有了依据
④ 算显存参数量 × 12 字节估全参；4bit 基座约四分之一算出来的数比卡容量小一半以上，才敢开训
# ③ 长度分布：这一步决定 cutoff_len，别凭感觉填
import numpy as np
lens = [len(tok(text)["input_ids"]) for text in all_texts]
print(np.percentile(lens, [50, 95, 99]).astype(int))
[ 312 1048 1830 ]
# 95 分位 1048 → cutoff_len 取 1024 或 1152。取 2048 是浪费，
# 取 512 会把两成长样本砍掉半个答案。

1.7B 这一档，三本账摆在一起看

方式显存大头量级24G 卡上的现实
全参 fp16权重 + 梯度 + 优化器约 20.6 G只剩 3G 给激活值，基本开不动
LoRA fp16冻结的基座 + 小补丁 + 优化器约 3.6 G宽松，batch 可以开大
QLoRA 4bit基座压到四分之一基座约 0.9 G本项目的选择：卡不紧，能开更大 batch

数字是 1.7B 量级的实测量级，随 batch、序列长度、梯度检查点开关浮动。算的时候留一半余量。

模板验不过，别急着开训。「下载完成」和「能用」之间差着一次 decode。最常见的错是拿通用模板去套一个自带模板的模型，拼出来的序列少了起始符或者多了结束符——损失照样降，效果就是不对。
这一章钉住了三件事
  • 钉住了：权重准备四步——下载、验模板、量长度、算显存，一步都不能省
  • 不这么做会：拿 2048 训练一个 95 分位只有一千的集，一半算力花在填充上
  • 下次遇到同类问题，先跑一次长度统计，再决定 cutoff_len 填多少
带走长度决定你花多少算力，显存决定你能开多大——两个数先量出来，再谈配置。

5配置准备：真正要改的只有六个旋钮

结论不管用 YAML 还是命令行，翻来覆去就是六个值：挂哪层、秩多大、学多快、吃多长、一批几个、跑几轮。其余字段都是这六个的衍生。
旋钮YAML 里的名初值怎么定改错的症状
挂哪层lora_target先用 all，跑通再收窄到注意力四件套只挂 q、v 常常不够；挂错层名会静默少挂
秩lora_rank16 起步。数据少往 8 降，学不动往 32 升太小欠拟合，太大在小数据上直接过拟合
学习率learning_rateLoRA 用 1e-4 到 2e-4，比全参大一个量级沿用全参的 2e-5，loss 几乎不动，以为模型不行
长度cutoff_len上一章量出来的 95 分位默认值 2048 悄悄生效，一半算力花在填充
批次batch × grad_accum显存允许的最大 batch，再用累积凑到 16 左右等效 batch 太小，loss 抖得看不出趋势
轮数num_train_epochs2 到 3。先看 val loss 拐点，别一上来就 10轮数过多，模型把训练集背下来，考卷上反而变差
configs/qwen3-1.7b-hyde.yaml（一份能跑的完整配置，去掉注释就十来行）
model_name_or_path: Qwen/Qwen3-1.7B
stage: sft
finetuning_type: lora
lora_rank: 16
lora_target: all
dataset: hyde_law
cutoff_len: 1024

per_device_train_batch_size: 2
gradient_accumulation_steps: 8   # 等效 batch = 2 × 8 = 16
learning_rate: 1.0e-4
num_train_epochs: 3.0
output_dir: runs/20261117_qwen3-1.7b_qlora_r16

开训前先看一眼可训参数

起训时，日志第一屏会打出这一行（LLaMA-Factory 自动给）
# trainable params: 8,798,208 || all params: 1,728,000,000 || trainable%: 0.51

这行数字是配置层的唯一体检。比例在 0.3% 到 1% 之间算正常；打出 100%，说明补丁根本没挂上；打出 0.01%，说明挂错了层或者秩填成了个位数。

框架的默认值会悄悄改你的实验。序列打包默认开、cutoff_len 默认 2048、学习率默认 2e-5 量级——这三项在你不知情的时候就已经定了结果。第一次跑，把配置里的默认值逐条读一遍，比盲目调参有用得多。
4bit 权重不能直接合并。要合回基座，先把量化权重反量化成 fp16 再 merge。直接在 4bit 上合并，精度掉得比训练本身还多。
这一章钉住了三件事
  • 钉住了：配置就六个旋钮——挂哪层、秩、学习率、长度、批次、轮数
  • 不这么做会：抄别人的配置但学习率沿用全参量级，loss 不动，误判成模型不行
  • 下次遇到同类问题，先看：日志里那行可训参数打出来是多少
带走配置不是抄来的，是量出来的——长度从数据来，批次从显存来，学习率从方法来。

6脚本骨架：五个入口，一条命令

结论一个微调仓库只需要五个入口：造数据、跑评测、训练、合并、推理。五个都抽成命令行参数，就能串成一条命令；串不成一条命令，说明还有东西写死在代码里。
脚本吃什么吐什么什么时候跑
prepare_data.py原始数据集data/sft/train.jsonl数据变了才跑，不是每次都跑
run_eval.py考卷 + 当前模型 / 检索器baseline.json 或 metrics.json训前一次，训后一次，同一条命令
train.py配置文件 + 训练集runs/<编号>/adapter每次实验；内部就是一行 llamafactory-cli train <配置>
merge.py基座 + adapter合并后的完整模型目录要部署或要换框架推理时
infer.py模型 + 一条输入一条输出每次训完，先人工看几条
一条命令从数据跑到 adapter
#!/usr/bin/env bash
# scripts/run_all.sh —— 参数全部从外面传，脚本里不写死任何路径
set -euo pipefail

CFG=${1:-configs/qwen3-1.7b-hyde.yaml}
RUN=${2:-runs/$(date +%Y%m%d_%H%M)}

python scripts/run_eval.py --out data/eval/baseline.json      # ① 基线
python scripts/train.py    --config "$CFG" --out "$RUN"       # ② 训练
python scripts/run_eval.py --model "$RUN/adapter" \
       --out "$RUN/metrics.json"                          # ③ 同一个尺子再量一次

三个让脚本「能重复跑」的细节

写死在代码里的东西，早晚会咬你一口
路径参数化
所有输入输出都从命令行或配置文件来。代码里出现绝对路径，就换不了机器——换机器第一件事就是全局替换路径，替换漏一处就跑不起来
断点续训
设 save_steps + resume_from_checkpoint。云端按量机器会被停、会被释放，没有断点，跑一半就是白跑
日志落盘
训练输出重定向到 runs/<编号>/train.log。终端滚屏没人能回看，而 loss 异常往往在几百步之前就出现了
别在一个脚本里连着做三件事。造数据、训练、评测写进一个文件，改一处就要重跑全部，而且中间产物不可查。分成三个入口，任何一个环节都能单独重跑——这不是工程洁癖，是省机时。
这一章钉住了三件事
  • 钉住了：五个入口——造数据、评测、训练、合并、推理，参数全部外置
  • 不这么做会：换台机器就要全局替换路径，漏一处就跑不起来，还得从头查
  • 下次遇到同类问题，先问：这个脚本我能不能只传参数就换一份数据、换一个模型
带走串不成一条命令，说明还有东西写死在代码里——先抽参数，再谈训练。

7台账与复现：让每次实验都留得下

结论微调的效果八成来自试，而试的前提是记得住。每跑一次，落一个编号目录、填一行台账——不记台账，第十次实验和第一次没区别。

一个编号目录，装下这次跑的全部证据

runs/20261117_1430_qwen3-1.7b_qlora_r16/
├─ config.yaml      # 这一跑用的完整配置，快照，不引用外部
├─ train.log        # 全程输出，出事往这儿翻
├─ adapter/         # 产出的补丁，几十 MB
├─ metrics.json     # 考卷上跑出来的数
└─ note.md          # 一句话：这次改了什么，为什么

note.md 只有一行字，但它是整份目录里最值钱的文件。三天后你会看着一个 adapter 想「这版是不是调了学习率那个」——没有这一行，你只能重跑一遍。

台账：一张表，每次一行

列记什么为什么非记不可
编号日期 + 模型 + 方法 + 关键变量目录名就是索引，不用打开就知道是哪一版
数据版本哪份 train、多少条、sha256 前 8 位数据换过一版，两次结果就不能直接比
配置r、学习率、cutoff_len、等效 batch、轮数这五个值一变，结论就可能翻
代价机时、花费、峰值显存算「这个提升值不值这些钱」，没有第二份数据源
结果主指标 + 回归指标 + 训了多少步只记主指标会漏掉「练坏了原来会的」
结论留、弃、还是改哪个参数再来一轮这一列决定下一次实验做什么

三个开关，把「可复现」落到实处

# ① 种子：四行，一个都不能少
import random, numpy as np, torch
SEED = 42
random.seed(SEED); np.random.seed(SEED)
torch.manual_seed(SEED); torch.cuda.manual_seed_all(SEED)

# ② 锁版本：装完立刻冻结，别等出事再回忆装了什么
pip freeze > requirements.lock.txt

# ③ 代码版本：跑之前先提交，别用脏工作区训练
git add -A && git commit -m "exp: qlora r16 lr1e-4"
git rev-parse --short HEAD >> runs/<编号>/note.md
「差不多能复现」是个陷阱。GPU 上的浮点运算顺序不固定，两次跑出来的 loss 不可能一字不差。可复现的标准不是「数字完全一样」，而是「同样的配置，结论不翻」——差在千分位以内算通过，差出一个点就要查是哪一步不一样。
一个便宜的验证法：挑一次跑，把 adapter 删掉、目录留着，用同一份配置重跑一遍，对比两条 loss 曲线的形状和最终指标。对不上，说明有东西没被配置捕获——通常藏在脚本里某个默认参数上。
这一章钉住了三件事
  • 钉住了：一个编号目录装五样东西，一张台账每次一行
  • 不这么做会：跑了十轮，只记得「有一版挺好的」，找不回来，等于只跑了一轮
  • 下次遇到同类问题，先看：这次跑用的数据是哪一版、代码是哪个提交——两个答不出，结果不可信
带走能复现的不是数字，是结论——配置、数据、代码三样对齐，结论才站得住。

8小结

结论这一课交出去的是一套能开训的配置：平台账号开了、线上验过三行、模型验过模板、配置量过长度、脚本串成一条命令。剩下的只有一件事：按下回车。
交付物落在哪验收看什么
开好的平台魔搭 Notebook 能开，AutoDL 账号能开机nvidia-smi 有输出，免费额度还剩多少心里有数
能跑的环境平台镜像，或一个 conda 环境 + 锁文件验证三行全过，pip freeze 有输出
验过的模型持久化盘上的权重目录模板 decode 过、长度分位有数、显存账算过
一份配置configs/*.yaml六个旋钮都有明确依据，可训参数比例正常
五个脚本scripts/一条命令能从头跑到尾，参数全部外置

开训前，九项自检

☐项怎么验
□平台账号能用一条命令能起，不用现注册现调试
□权重在持久化盘魔搭是持久化盘、AutoDL 是 autodl-tmp，系统盘里没有权重
□验证三行全过torch CUDA 版、四个包能 import、nvidia-smi 认卡
□一个框架一个环境三个入口不在同一个 conda env 里
□模板 decode 过角色标记与结尾符跟基座一致
□长度分位有数50 / 95 / 99 三个数，cutoff_len 有依据
□可训参数正常0.3% 到 1% 之间，不是 100% 也不是 0.01%
□断点续训开着有 save_steps，知道从哪恢复
□台账建好了runs/ 和台账表都在，第一次跑就能填

四条边界，越界就要返工

  • 平台先于调参。账号和环境没定，就在本地调配置，等于白调——卡型一换，长度和批次全要重算。
  • 一个框架一个环境。混装省的那十分钟，后面会用一整天来还。
  • 配置贴着机器调。本机调好的配置搬到另一张卡上，长度和批次都要重算。
  • 没台账就不算做过。跑完不记，下一轮从零开始猜。
下一步到这里，需求和数据看清了、平台和仓库装好了。下一课按下第一次回车：看 loss 怎么走、什么时候该停、产出的 adapter 怎么验证、第一版结果怎么读。真正的坑从那时候才开始。
这门课留下的判据
  • 判据一：平台给什么就用什么，别自己从零搭环境——超过一小时就换路
  • 判据二：框架管流程、内核管速度，两者能叠，选哪个看你要不要改内部
  • 判据三：长度从数据量出来，批次从显存量出来，学习率从方法量出来
  • 判据四：串不成一条命令，说明还有东西写死在代码里
带走账号开好、三行验过、模型验模板、配置量长度、脚本串一条——五样齐了，才配按下第一次回车。
