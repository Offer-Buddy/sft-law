1这个项目做什么

结论这个项目只做一件事：给一个法律问题，模型直接说出它该走哪部法——50 部里选 1 部。

真实场景是这样：用户丢来一句「离职后公司一直拖着不发工资，我该找哪部法？」——人要回答，得先翻法条、判关系，慢且不稳。

要解决的事不是「答案写得好不好」，是「先归对哪一类」。归错了部法，后面的检索和回答全白搭。

所以这一课不训「会答法律题」的模型，训一个「会分案」的模型。它只输出一个词：劳动法。

这个项目产出的三样东西
数据
22,922 条「问题 → 部法」标注对，50 类，train / val / test 零重叠
模型
Qwen3-1.7B 的 QLoRA 适配器，单卡 4090 一两小时训完
尺子
一套可复算的评测：accuracy、macro-F1、top-3、混淆矩阵
  • 这个项目是分类，不是问答：输出一个部法名，不是一段答案。
  • 不带检索、不带知识库，纯看「归对没归对」。
  • 三样产出：数据、模型、尺子，缺一样都算没做完。
一句话带走先归对部法，才谈得上答对问题——这个项目训的就是「归对」这一步。

2为什么是分类

结论同样是微调，做分类不做问答，因为分类的对错机器能直接判，问答不能。

同一份数据，至少能训出四种东西。差别不在难度，在「做完怎么知道你训成了」。

候选任务数据够不够怎么验证碰知识库吗
法律问答Pair 7.9 万条够，但答案好坏没有标准基本没法量化不用
问题改写缺「口语」那一头，现成数据是书面语要看检索命中要
意图识别没有「咨询 / 投诉」标签，得另造看分类准确率不用
部法分类reference 里的法条名就是现成标签准确率一算就有不用

四行看完，选谁不用犹豫：只有部法分类同时满足「标签现成、验证直接、不碰知识库」。

最容易走岔的一步看到「法律」两个字就往「问答」上靠。问答训出来的是「会说」，但说不清好不好；分类训出来的是「会判」，判错一条当场看得见。教学要的是看得见。
必答题既然只做 50 类分类，为什么不直接用 BERT 加一个分类头？因为这一课的重点不是「分类」两个字，是把一条微调链完整走通。换 BERT 就要换数据格式、换训练脚本、换评测方式，前面学的全作废。而 Qwen3 这条链训完的适配器能卸、能合、能继续拿去做生成，分类头训完就锁死在分类上。

代价也得认：如果只做分类、只追求推理便宜，BERT + 分类头确实是更省的选择。这里选生成式，是因为整门课的主线要能贯通，不是因为分类头不对。

  • 四种任务里，问答验证弱、改写缺数据、意图缺标签，只剩分类能撑住。
  • 分类的「对错」由标签决定，不依赖人读着像不像。
  • 选任务的判据不是「哪个高级」，是「哪个做完能证明」。
一句话带走数据里有什么标签，就训什么任务——reference 标了部法，就做部法分类。

3数据怎么变标签

结论Triplet 每条问答的 reference 早就标了「该命中哪条法」，把法条名抽出来，就是 50 类标签。

原始数据长这样：一条样本里塞着几条法条原文、一个真问题、一段答案。我们只要两样——问题和它的部法。

清洗只剩三条规矩，每条都对应一个坑：

规矩为什么不做会怎样
必须剥掉 input 里的法条法条原文是答案，留着等于把答案喂给模型模型学会抄法条，不学会判部法
多部法的样本取多数80 条样本 reference 跨两部法，单标签任务只留一个标签打架，训练信号乱
评测集问题必须剔除evalset 和训练集同源，不剔就「偷看考卷」准确率虚高，一上真实数据就掉

加工完的一条，长这样

1data/cls/train.jsonl 第一条query / response 两字段
# query
请判断以下法律问题应适用哪部法律。只输出法律名称，不要解释。

问题：小王是一家个人独资企业的投资人，他的企业已经解散，
但仍有未偿还的债务，他需要承担什么样的偿还责任？
收回的财产如何分配？

# response
个人独资企业法
指令为什么这么短只写「判哪部法 + 只输出法名」两句。指令越长，模型越爱在输出里补解释，后面的候选打分反而不好比。
答案为什么只有一个词response 放部法名本身，不放「该问题应适用《个人独资企业法》」这种整句——整句会让每个候选的 token 数不一样，打分时不好比长短。

原始 reference 里的法条名本身就很干净，50 部法没有一个带「中华人民共和国」前缀，不用额外做归一化。这一点省了不少事，但不是所有数据集都这么善良——换数据时要先查一遍。

  • 标签不是人标的，是 reference 里现成的法条名，零标注成本。
  • 清洗的核心是「把答案挡在输入之外」，三条规矩都服务这一条。
  • 剔除评测集问题不是可选项，漏了整份准确率都不可信。
一句话带走好数据的标志不是量大，是「输入里没有答案、标签没有歧义、考卷没有混进训练」。

4五十类怎么摆

结论50 类不均衡，最大民法典 3,727 条、最小公益事业捐赠法 93 条，所以不能只看 accuracy。

清洗完剩下 22,922 条，50 个部法全都有人，没有空类。但大小差得很远：

排名部法样本数位置说明
1民法典3,727最大类，占全部约 16%
2刑法1,800与刑事诉讼法只差两个字
3刑事诉讼法1,131极易与刑法混
4证券法978金融类代表
5民事诉讼法975极易与民法典混
………中间 44 类从 94 到 889 条
50公益事业捐赠法93最小类，只有大类的 1/40

上表只列头尾。完整 50 类清单在 data/cls/label_stats.json 里，打开就能看到每类条数——做候选打分时直接读这个文件，别手抄标签。

这个分布带来三个后果：一个要换尺子、一个要防坑、还有一个提醒你别太信小类的数。

不均衡逼出的两个决定
尺子
主指标不能只报 accuracy——大类刷分能掩盖小类全错，必须同时看 macro-F1
坑
民法典 / 民事诉讼法、刑法 / 刑事诉讼法，名字像、内容近，模型最容易在这两对上翻车，评测要单独看混淆矩阵
还有个更隐蔽的后果：小类的结论不稳切分是按比例分层的，大类切完还剩几千条，小类就惨了——公益事业捐赠法进训练集只剩 70 条，进 test 只剩 8 条。8 条里错 1 条就是 12.5 个百分点，所以小类的准确率会剧烈抖动，macro-F1 有相当一部分是被这几个小类牵着走的。报数时必须带上「这一类 test 有几条」，只报百分比等于没报。
  • 50 类无空类，但最小类进训练集只剩 70 条，属于「能起步、学不充分」。
  • 类别差 40 倍，accuracy 会被大类带偏，macro-F1 才是公平尺。
  • 两对名字相近的部法，是混淆矩阵里最先暴露的问题。
一句话带走类别不均衡时，先问「小类错了没」，再看总分——否则总分骗你。

5训练怎么配

结论Qwen3-1.7B + QLoRA 4bit，LLaMA-Factory / Unsloth，单卡 4090 一两小时一轮。

分类任务比生成任务轻：输出只有一个词，不用长上下文。配置可以压得很省。

项取值为什么
基座Qwen3-1.7BApache 2.0，中文友好，1.7B 单卡可训
方法QLoRA 4bit（NF4 + 双量化）基座权重从 3.4G 压到 0.9G，省下的全给激活值
框架LLaMA-Factory（AutoDL）+ Unsloth主线；魔搭上换 ms-swift 同款参数
LoRAr=16 / α=32，attention + FFN分类任务 r=8 也够，16 留余量
学习率2e-4，cosine + warmupQLoRA 常用档，高了发散、低了欠拟合
epoch250 类收敛快，1 可能欠、3 易过拟合
max_len512问题最长 333 字 + 指令，512 足够

显存账：24G 有一半是空的

先算账，再选卡。QLoRA 把基座压成 4bit 之后，真正吃显存的不是模型本体，是激活值：

项占用说明
基座（NF4 + 双量化）≈ 0.9 G1.7B × 0.5 byte，权重固定不动
LoRA 权重 / 梯度 / 优化器≈ 0.3 G可训参数约 20M，r=16 挂 attention + FFN
激活值≈ 2~4 G最大变量，随 batch × 序列长度线性涨；开梯度检查点能压住
CUDA 上下文 + 碎片≈ 1~2 G框架固定开销，省不掉
合计≈ 5~7 G24G 卡真实占用不到三分之一

分类任务的账特别轻，原因只有一个：max_len 只要 512。生成任务的改写器要 768~1024，光激活值就差一倍。

卡型显存能跑到什么程度
4060Ti / 30708 Gbatch 压到 2~4，max_len 降到 384，对照实验得关掉
3060 12G / 407012 Gbatch 8 稳跑，全流程跟得下来——个人机首选
4090 / A10 / 309024 Gbatch 16 无压力，还能留余量做对照实验——推荐
A100 40G / 80G40 G+1.7B 根本用不满，纯属多花钱
最容易翻车的演示想现场跑「全参 vs QLoRA」对照——全参 1.7B 训练要 20G 以上，24G 卡卡在 OOM 边缘，一崩就掉课堂节奏。全参只讲数字，现场只跑 QLoRA。

数据侧三份文件已经切好，直接喂：

$ wc -l data/cls/*.jsonl
  18338 data/cls/train.jsonl
   2292 data/cls/val.jsonl
   2292 data/cls/test.jsonl
  • 1.7B + QLoRA 是「能跑通、能反复实验」的体量，不是「效果最好」的体量。
  • 分类任务 max_len 512 就够，别照搬生成任务的 2048。
  • epoch 从 2 起，看 val 准确率停，不靠感觉。
一句话带走先定显存账，再定参数——1.7B 的 QLoRA 账算完，4090 上什么都塞得下。

6怎么算做成

结论不让模型自由生成，把 50 个部法名逐个打分取最大——既不出幻觉，又能算 top-3。

生成式分类最大的坑是「说漏嘴」：模型可能吐出「民法典第一编」这种不在标签集里的词，字符串一匹配就判错。

错法：自由生成再匹配
prompt: 这题该用哪部法？ 模型: 《民法典》第一编... 匹配: 不在 50 类里 → 判错
代价：模型其实知道是民法典，却被判错；准确率被白白拉低。
对法：50 个候选逐个打分
for law in 50_labels: score = logprob(prompt, law) pick = argmax(score) top3 = 前 3 个 score
收益：输出必在 50 类内，还能顺手给 top-3。
候选打分有个真陷阱：长度没归一化「民法典」是 3 个 token，「国际刑事司法协助法」是 9 个。直接把整句 logprob 加起来比，token 多的标签天然分更低——模型不是觉得民法典更像，是被标签长短带了节奏。必须按 token 数取平均： 
score = sum(logprob(t) for t in label_tokens) / len(label_tokens)
漏了这一步，混淆矩阵里会冒出一批「本该判长名法条、却判给短名法条」的错案，原因不在模型，在打分代码。

混淆矩阵怎么读

50×50 不需要全看，只读三处：

  • 对角线——每一类判对的条数，格子越亮越好；
  • 行和——这一类总共有多少条，是算这一类的分母；
  • 非对角线最亮的格子——病灶。重点盯刑法 → 刑事诉讼法、民法典 → 民事诉讼法这两格，问法本身就模糊，最容易串。

所以报结论别说「准确率 88%」就完事，要说「民法典被判成民诉法吃掉了多少条」——这才叫指到病灶。

四把尺子一起看，缺一把都会误判：

指标回答什么问题怎么读
accuracy50 选 1 整体对了多少主指标，但会被大类带偏
macro-F1每一类平均好不好小类错了立刻掉，最公平
top-3差一点就对的有多少看模型「接近对」的能力
混淆矩阵具体混在哪两对重点看民法典/民诉、刑法/刑诉
别忘了先量 zero-shot 基线不微调的 Qwen3-1.7B 直接做同样 50 选 1，准确率先记下来。没有这个数，「微调后 88%」说明不了任何事——得看它比基线高了多少。
  • 候选打分替代自由生成，是分类任务评测的第一道保险。
  • accuracy 看总分，macro-F1 看公平，top-3 看接近度，混淆矩阵看病灶。
  • 没有 zero-shot 基线，所有提升数字都站不住。
一句话带走评测不是「跑一个准确率」，是「先有基线、再有多把尺子、最后能指到病灶」。

7整条线怎么走

结论整个项目六步：数据 → 基线 → 训练 → 评测 → 对比 → 交付，每一步都有可验收的产出。
步做什么产出怎么算过
1造数据data/cls/ 三份 jsonl + 标签统计50 类无空类、零重叠
2量基线zero-shot 的 accuracy / macro-F1有具体数字落在报告里
3训模型LoRA 适配器 + 训练日志val 准确率不再涨
4评效果test 三指标 + 混淆矩阵能指到最差的两类
5做对比基线 vs 微调 一张对照表提升幅度说得清
6交付模型 + 数据 + 评测报告别人照着能复现这组数

这条线背后只有一句判断：每一步都要留下一个「能被别人复算」的东西。数据要能重建，基线要能重跑，评测要能重出。

最常见的塌方点跳过第 2 步直接训。训完发现准确率 85%，挺高兴——但没人知道不训是多少，这个 85% 到底是模型强还是任务简单，说不清，整份工作就白做了。
  • 六步是一条闭环：数据进、数字出、报告收。
  • 基线不是可选项，它是「微调有用」的唯一证据。
  • 交付的判据是「别人能复现」，不是「我跑通了」。
一句话带走项目做成不是「模型能跑」，是「每个数字别人都能重算一遍」。

8小结

结论这一课铺了地图：任务是 50 类分类，数据是 22,922 条「问题→部法」，尺子是准确率加 macro-F1。

下面三张表把这一课收住：动了哪几层、几条边界不能越、几步自检能独立验。

层这次动了什么没动的部分
数据层 data/cls/新增 50 类训练对、三份切分、标签统计原始 Triplet 只读，一条没改
任务层从「生成答案」改成「50 选 1 分类」基座、量化、框架三层照旧
评测层新增候选打分 + macro-F1 + 混淆矩阵不碰检索，不建索引

三条边界，越界就要重做

  • 输入里不许有答案问题里夹着法条原文，模型就只在抄，不在判——这是最容易悄悄破坏整份训练的一步。
  • 评测集不许进训练evalset 的问题哪怕只漏几条进 train，准确率就不可信，整份报告作废。
  • 没有基线不许报提升只报「微调后 88%」而不报「基线多少」，等于没做实验。

三条自检

每一步都能单独验，不用等全跑完
① 数据打开 label_stats.json：类别数=50、无 0 条类、三份切分互不重叠
② 基线不加载适配器跑一次评测，数字必须明显低于微调后，否则任务太简单
③ 评测混淆矩阵里能指出「最差的两类是谁」，指不出就是没看
下一步地图看完，下一课进「怎么选基座、怎么定量化、框架搭哪层」——把这一课的方案落成能开训的环境。
  • 任务是分类不是问答：因为分类的对错机器能判。
  • 标签是 reference 里现成的部法名：零标注成本。
  • 验收靠基线 + macro-F1 + 混淆矩阵三件套：缺一件都说不清。
带走拿到任何一份「问题→标签」的数据，先问三句：标签现成吗、输入里有答案吗、考卷混进训练了吗——三句都过，才谈得上开训。
