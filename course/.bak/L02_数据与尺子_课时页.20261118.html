1前四环落成三个文件

结论需求卡定「做什么」，训练集定「学什么」，考卷加基线定「算不算成」。三个文件缺一个，开训就是盲训——训完既说不清学会了什么，也说不清好没好。
文件里面是什么谁消费它缺了会怎样
需求卡四段定位、一句话成功标准、这次不做什么你自己，三周后；接手的人做完没人能判断该不该上线，评审会上只能讲过程
训练集 + 验证集input / output 成对，切好的 train / val训练脚本、数据加载器没有料，整条链子断在第一步
考卷 + 基线题、标准答案、训前跑出来的那个数评测脚本、A/B 对比训完只能说「感觉顺畅多了」
目录长这样，后面每一步都往里放东西
sft-law/
├─ data/
│  ├─ raw/      # 原始数据集，只读。永不修改，改了就无法回溯
│  ├─ sft/      # train.jsonl / val.jsonl —— 喂给训练的
│  ├─ eval/     # evalset.jsonl / baseline.json —— 判好坏的
│  └─ corpus/   # 检索目标库（比如 6432 条法条）
├─ configs/     # 一次实验一份配置，跟实验编号对应
├─ scripts/     # 数据、评测、训练、合并、推理五个入口
└─ runs/        # 每次跑的日志、adapter、指标，一个都不丢
为什么先分目录数据在微调里改动的次数远多于代码。目录一分，你永远知道手上这份 train.jsonl 是哪一版、由哪份原始数据、哪个脚本、哪个随机种子生成的——这三个信息丢了，任何复现都是空话。
这一章钉住了三件事
  • 钉住了：前四环的结论要落成三个文件——需求卡、训练集、考卷加基线
  • 不这么做会：直接冲进训练，训完发现没有题可测，只能凭感觉收工
  • 下次遇到同类问题，先问：我这三个文件有哪几个是真的在磁盘上的，哪几个还只在脑子里
带走数据和尺子都是文件，不是想法——落在磁盘上才算备过。

2需求卡：把「要解决什么」写成一页

结论需求卡不是给领导看的立项书，是给你自己三周后看的证据——证明当初为什么不用改 prompt、为什么非要训。四块内容，一页写完。
块写成什么样反例（这么写等于没写）
① 失败在哪段指出四段中的一段：理解输入 / 取资料 / 组织输出 / 兜底规则，并附一条真实例子「模型答得不准」「用户反馈不好」
② 谁在什么场景一类用户、一个入口、一个动作。带上入口名或日志里能搜到的关键词「所有用户」——等于没有场景
③ 成功标准一句话，且这句话能翻成一个指标名和一个方向「回答更像律师」「体验更好」
④ 这次不做列三条以上：不管的语种、不管的场景、不追的指标空着——范围会一路膨胀到做不完

第 ③ 块是整张卡的命门。它必须能直接翻译成第 7、8 章要建的那个数。翻不成的，说明需求还没想清，退回上一课第 4 章，别往下走。

翻不成指标的写法
让模型更懂劳动法 回答要专业、准确、有依据 口语问题也要答得出
三句都对，但没有任何一句能变成一个可计算的数。
翻得成指标的写法
口语提问经改写后，目标法条进 top-5 的比例 从 72.5% 提到 85% 书面语那部分不许掉超过 1 个点
指标、方向、底线三样齐了，后面所有比较都有落点。
第 ④ 块最容易被跳过，也最容易救你。不写「不做什么」，两周后一定有人问「能不能顺便把合同审查也做了」。写在卡上，才有话可回：这一版不做，下一版再说。
把「不用别的办法」也写进去。在卡上补两行：改 prompt 为什么不够（约束写到多少字还是压不住）、加检索为什么不解决问题（问题出在 query 侧，不在库里）。这两行是你三个月后被质疑时的第一道防线。
这一章钉住了三件事
  • 钉住了：需求卡四块——失败在哪段、谁在什么场景、成功标准、这次不做
  • 不这么做会：范围一路膨胀，最后交付的东西跟最初的失败点已经没关系了
  • 下次遇到同类问题，先问：成功标准那句话，能不能直接翻成一个指标名和一个方向
带走成功标准翻不成指标，说明需求还没想清——别拿训练去填补这个空白。

3IO 规格：一条样本到底怎么拼

结论模型学的就是「你拼出来的那个字符串」。三段：系统提示、用户输入、目标输出，中间用基座认识的模板连起来。模板错一个 token，训出来的东西就差一个档次，而且不报错。
段写什么写错会怎样
系统提示角色、任务、输出边界。这段是不变的那部分，每条样本都一样写得含糊，模型只能从样本里猜你要什么；写得啰嗦，会挤占有效长度
用户输入线上真实会进来的那句话，口语、错别字、说一半就停，都照原样保留改写成规范书面语，等于在教一个线上不存在的场景
目标输出你想要它吐出来的那个样子，长度、句式、结尾都照线上标准来答案里带解释、带招呼语，模型会把这些一起学走

本项目要训的是 HyDE 改写器：用户口语问一句，模型输出一段带法律概念的检索用文本。系统提示是固定的，长这样：

# scripts/prepare_hyde_sft_data.py 里的 make_prompt
请根据用户法律问题生成一段用于语义检索的假设性法律文档。
要求包含核心法律概念、可能涉及的法律关系、责任类型和检索关键词；
不要给用户建议，不要写结论，只输出检索用文本。

用户问题：老板让我天天加班不给钱

这条提示里有三处约束在干活：「假设性法律文档」定文体（不是回答，是文档）、「不要给建议、不要写结论」砍掉跑偏（模型最容易滑向的地方）、「只输出检索用文本」定边界。少任何一句，训出来的东西都会往问答方向滑——因为它见过太多问答。

模板是硬约束，不是风格问题

拼好的三段不能直接用字符串粘起来，必须过基座的 chat 模板：

msgs = [
    {"role": "system", "content": SYSTEM_PROMPT},
    {"role": "user",   "content": question},
    {"role": "assistant", "content": target},
]
text = tokenizer.apply_chat_template(msgs, tokenize=False)
print(repr(text[:200]))   # 开训前一定打出来看一眼
Qwen 系打印出来大致是这个形状（特殊标记已替换成可读文字）
IM_START system
请根据用户法律问题生成一段用于语义检索的假设性法律文档……
IM_END
IM_START user
老板让我天天加班不给钱
IM_END
IM_START assistant
用人单位安排劳动者延长工作时间的，应当支付不低于工资百分之一百五十的报酬……
IM_END
模板不一致，效果断崖，而且不报错。基座在预训练和对齐时用的是某一套角色标记，你微调时换成另一套，模型看到的就不是它熟悉的对话结构。损失照样下降，曲线照样好看，上线就是不对。唯一的检查办法是把一条样本 decode 出来，用眼睛看。

两个必须掐掉的泄露点

公开数据集看着是「现成的问答对」，直接用往往出事。以 DISC-Law Triplet 为例，一条记录的字段长这样：

{"input": "<问题>：老板让我天天加班不给钱",
 "reference": ["《中华人民共和国劳动法》第四十四条：……"],
 "output": "用人单位安排劳动者延长工作时间的，应当支付不低于百分之一百五十的报酬。"}
  • 标记是噪声。input 不是一句干净的话，是带标记的整段文本。整段喂进去，模型会连标记一起学——它学会了遇到标记就吐答案，而不是学会听懂人话。要用正则把真正的问题抠出来。
  • 参考法条是答案。reference 里就是这条问题该命中的法条原文，也正是输出里要引用的内容。把它放进输入，模型是在抄，不是在学改写。参考字段只能用于造语料和造考卷，不能进训练输入。
判断口诀问自己一句：这条样本里，模型在训练时能看到的那些字，线上推理时它能看到吗？看不到的，一律要删。这是区分「训练数据」和「答案纸」的唯一标准。
这一章钉住了三件事
  • 钉住了：一条样本是系统提示 + 用户输入 + 目标输出，中间必须过基座的 chat 模板
  • 不这么做会：模板错、标记没清、参考法条漏进输入，loss 一路下降但线上完全不能用
  • 下次遇到同类问题，先问：输入里这些字，线上推理时模型能看到吗——看不到的删掉
带走模型学的就是你拼出来的那个字符串——拼错的地方，它一个字都不会放过。

4清点：手上这批料能训什么

结论清点不是数条数，是逐个字段问「这一列能不能当标准答案」。能，就照着它定任务；不能，要么换任务，要么先造数据——没有第三条路。

先做一张表，把手上的每个文件点清楚。这张表一填完，任务形态基本就定了：

文件条数关键字段哪列能当答案缺什么
Triplet23,331input / reference / outputoutput（法律问答答案）没有「口语改写」的标注
Pair79,692input / outputoutput（问答答案）同上，且没有法条锚点
法条语料6,432key / text没有答案列是检索目标库，不是训练数据

本项目口径：用法条 6,432 条 / 50 部；Pair 只作对照，不用于训练。

填完这张表，会发现一个硬事实

Triplet 的 output 是「法律问题的答案」，不是「这个问题的检索改写」。你想训改写，手上没有改写的标注——这不是数据量不够，是标注字段对不上。上一课第 3 章说的那句「标注字段决定任务形态」，落到具体项目上就是这件事。

可选任务需要什么标注手上有没有
法律问答生成问题 → 答案有，Triplet 的 output 就是
query 改写口语问题 → 标准检索式没有。公开集里没有这种标注
HyDE 假设文档问题 → 一段含法律概念的检索文本可以造：答案本身就能当那段的来源
为什么绕到 HyDE既然没有「改写后的话」这种标注，就换一个同样能提升检索、但目标文本可以造出来的任务：让模型把口语问题写成一段「假设的法条式文本」，再拿这段文本去检索。目标文本从答案里裁——答案本身就是法条语体，截前 700 字正好是那段文档。任务换了，标注的需求就绕开了，而验收指标还是同一个：目标法条进没进 top-k。
换任务是允许的，换验收指标是不允许的。任务可以为了适配数据而变形，但第 7、8 章的考卷和指标必须从头到尾是同一把尺子。任务一改就把指标也改掉，两次结果就没法比了。
动手：给自己的数据填一张清点表
  1. 列出所有原始文件，逐个写明条数、字段名、许可（能不能商用）。
  2. 对每个文件回答一句：哪一列能当「标准答案」，为什么。
  3. 把「想训的任务」和「有标注的任务」并排写在纸上，中间差的那一格，就是你接下来要造的东西。
这一章钉住了三件事
  • 钉住了：清点的产出是一张表——每条数据的条数、字段、哪列能当答案、缺什么
  • 不这么做会：拿「问题→答案」的数据硬训改写，训出来的模型只会答题，不会改写
  • 下次遇到同类问题，先问：我想要的目标输出，在现有字段里有没有对应的那一列
带走没有对应的标注列，就别在模型上硬拧——换任务，或者先造数据。

5造训练对：从原始字段拼出 input/output

结论造数据这一步只有四个动作：读出问题、洗掉噪声、套上系统提示、配一段目标文本。整个脚本不到一百行，但它决定了模型到底在学什么。

拿本项目说，输入侧要的是「用户原话」，输出侧要的是「一段法条语体的检索文本」。原始 Triplet 里两样都没有现成的，得从字段里加工出来：

动作做的是什么为什么非做不可
提出问题用正则从带标记的整段文本里，抠出真正那句问话不抠，标记会被当成特征学进去
洗掉噪声合并空白、去首尾、丢掉空答案的坏行空白字符在 token 层面是真实存在的，会白白吃掉长度
套系统提示把第 3 章那段固定提示拼在问题前面推理时也会带这段，训练不带就是两套输入分布
配目标文本从答案里裁前 N 字，作为要学的那段文档答案动辄上千字，学全篇既慢又偏——检索要的是关键词密度，不是完整论证
scripts/prepare_hyde_sft_data.py（四步串起来）
def extract_triplet_question(text: str) -> str:
    # 带标记的整段文本 → 真正那句问话
    m = re.search(r"<问题>\s*[：:]\s*(.+)", text, flags=re.S)
    return clean_text(m.group(1), max_chars=1000) if m else clean_text(text)

def clean_text(text: str, max_chars: int) -> str:
    # 合并空白 + 截断。空白不是"看不见"，它会实打实占 token
    return re.sub(r"\s+", " ", text).strip()[:max_chars].strip()

# 一条样本 = 固定提示 + 用户问题  →  从答案裁出的目标文本
row = {"input": make_prompt(question),
       "output": clean_text(answer, max_chars=700)}
$ python scripts/prepare_hyde_sft_data.py --max-answer-chars 700
读到 Triplet 23331 条 / Pair 79692 条
产出 23331 条 → data/sft/hyde_sft_train.jsonl

三个参数，每个都有代价

动手之前先想清楚，动手之后就别改
裁多少字
默认 700。短了丢关键概念，长了学到整篇论证。判断办法：随机抽 20 条，看 700 字里还有没有那条法条的核心表述——有就够，没有就往上调到 1200 再抽一次
用哪个源
Triplet 的答案带法条锚点，Pair 没有。要训检索用的文档，优先 Triplet；Pair 只作补充或对照，别混着训——两批数据的目标文本风格不一样，模型会学到两种口径
随机种子
固定 --seed 42。抽样、切分、打乱全用它。种子不固定，换个时间重跑就得到另一份数据，后面任何一次对比都失去意义
坏行是静默跳过的。脚本里 except json.JSONDecodeError: continue，一行坏数据不会让程序停下来，也不会告诉你。真正的安全做法是打印计数：读进多少、跳过多少、产出多少，三个数对不上就当场查。同理，re.search 没匹配上的行会被整段兜底当问题用——数量对不上时，先怀疑这一条。
截断会截在半句上。700 字硬切，最后一句经常是断的。多数情况下无害，但如果你的目标文本必须句式完整（比如要让模型学会固定的结论句），就得在切点往回找最近的句号。这一点要写进脚本，不能靠运气。
这一章钉住了三件事
  • 钉住了：造数据就是四步——提出问题、洗掉噪声、套系统提示、配目标文本
  • 不这么做会：原始字段直接进训练，标记变特征、参考法条变答案，训出来的模型在线上完全不对
  • 下次遇到同类问题，先看：读进、跳过、产出三个数对不对得上——对不上就是有行被静默处理了
带走造数据不是在整理文件，是在决定模型学什么——每个筛选条件都是一次教学取舍。

6清洗、切分与数据卡

结论数据进训练前要过四道闸：重复、长度、坏样本、泄露。过完切成 train / val，再写一张数据卡。这四道里，泄露检查是唯一会让所有努力归零的那道。
闸怎么查查到之后怎么办
重复问题做归一化（去标点、转小写）后取哈希；答案取前 50 字哈希同问题保留答案最长的一条；同答案不同问题要警惕——可能是同一个模板批量生成的
长度统计 token 数的 50 / 95 / 99 分位95 分位就是 cutoff_len 的初值。定太短，长样本被切掉半个答案；定太长，每步都在算填充
坏样本空答案、答案长度小于 20 字、乱码、答案与问题高度重合直接删，别修。修一条的时间够你造十条新的
泄露考卷的每个问题，在训练集里做精确匹配和近似匹配训练集里出现的，从训练集删——不是从考卷删

切分：三份，各干各的

集合比例拿来干什么能不能动
train约 90%训练，梯度只从这份来随时可调
val约 5%看有没有训过头：val loss 开始回升就是信号可调
考卷200 条起验收。训前训后各跑一次，只认这个数锁死，定了就不许再碰
val 不是考卷。val 参与了「什么时候停」这个决策，所以它已经间接被用来调整过模型。真正能当裁判的，只有从头到尾没参与过任何决策的那份题。两份混着用，等于自己当运动员又当裁判。

数据卡：一页纸，让三个月后的你能接手

字段写什么
来源与许可原始数据集名称、版本、许可（能不能商用）、下载日期
条数原始条数、清洗后条数、train / val / 考卷各多少，掉了多少、为什么掉
构造规则系统提示原文、目标文本从哪个字段裁、裁多少字、种子多少
已知缺口哪类问题覆盖少、哪种说法没见过、哪个法条样本只有一条
不要做什么这份数据训出来的模型不该用来干什么（比如：不能当法律意见、不能答程序性问题）
数据卡最后一行比前面都重要。一份用问答数据训出来的改写器，最容易被误用成「法律咨询助手」。写清「不该干什么」，是在保护使用者，也是在保护你自己。
这一章钉住了三件事
  • 钉住了：四道清洗闸加一道泄露检查；切成 train / val / 考卷三份，考卷锁死
  • 不这么做会：考卷的题混在训练集里，训完指标漂亮得不像话，上线一测打回原形
  • 下次遇到同类问题，先做泄露检查：考卷里的每一个问题，训练集里到底有没有
带走清洗只影响效果，泄露会让所有数字化成假的——先查泄露，再谈清洗。

7造考卷：怎么造才不作弊

结论考卷三条件：独立于训练、贴着线上分布、有能判对错的标准答案。三条里最容易被牺牲的是第二条——而它恰恰决定这个数有没有意义。
条件具体要求不满足会怎样
独立不参与训练、不参与挑模型、不参与定超参模型见过答案，指标虚高，上线就掉
贴分布题面的说话方式、长度、错别字，照着线上日志来训完提升的是「答书面题」的能力，线上一点用没有
可判每题有一个明确的正确结果：法条 key、类别、或人工评分标准只能人眼看，两个人打出两套分

本项目的做法：抽题、改写题面、不动答案

# ① 从 Triplet 抽一批题，连同它们该命中的法条 key 一起留下
python scripts/build_baseline.py evalset --size 400

# ② 题面是书面语，让大模型把它改写成口语（标注一个字都不动）
#    "用人单位应当如何支付加班工资"
#      → "老板让我天天加班不给钱，这算不算违法"
# ③ 人工过一遍：改写后还是不是同一个问题，不像就丢掉
关键改写只动题面，标准答案（那一组法条 key）一个字都不改。这样考卷既贴了线上分布，又保持了可判性——用模型改写题面不会污染标准答案，这是它和「用模型造答案」的根本区别。

这组数说明为什么非要贴分布

考卷条数hit_rate@5MRR没进 top-5
书面语（全量）40079.75%0.653881 条
书面语（抽样对照）4077.50%0.70639 条
口语（同一批题改写）4072.50%0.579211 条

同一份法条语料（6,432 条）、同一个向量模型（bge-small-zh-v1.5）、同一个 top-5，只把题面从书面语换成口语：命中率掉 5 个点，MRR 掉 0.13。

小样本的命中率要谨慎读。40 条里对错各一条，就是 2.5 个点。所以 40 条上的差距只能看方向，不能当结论；要下结论至少 200 条起。用 400 条那组做验收，40 条那组只用来快速自查。

锁死考卷：三个动作

不锁死的考卷，迟早会被你自己改掉
记指纹
算一遍文件 sha256 记到数据卡里。以后每次跑评测先核对指纹，对不上就说明考卷被人动过
设只读
文件权限改成只读，脚本里对评测集一律只 open(..., "r")。想加题，开新版本，不动旧文件
带版本号
文件名或字段里带版本，比如 evalset_v1_oral.jsonl。所有指标记录都必须写清用的是哪一版
两个常见的自欺。① 拿训练集里的题当考卷——数字会高得让你以为做成了。② 拿模型自己生成的答案当标准答案（自评）——模型答错的地方，自评也会判对。标准答案只能来自人工或原始标注，不能来自你要评估的那个模型。
这一章钉住了三件事
  • 钉住了：考卷要独立、贴线上分布、可判；改写只动题面，标准答案不动
  • 不这么做会：用书面题考一个要在口语场景落地的模型，考出来的分和线上没有关系
  • 下次遇到同类问题，先问：这套题里，有没有一道是从训练集里来的
带走考卷的题面要像线上，标准答案要像标注——两样混了，这个数就废了。

8跑基线：训前那个数

结论基线是「不微调的情况下，这套题能拿多少分」。它必须在你写第一行训练代码之前跑出来，否则后面所有「提升了」都没有起点。

三条命令，三步走。第一次全跑，之后只重跑第三步：

# ① 从 Triplet 的 reference 里抽法条，去重成检索目标库
python scripts/build_baseline.py corpus
# ② 抽题 + 标准法条 key
python scripts/build_baseline.py evalset --size 400
# ③ 建索引、跑检索、算 hit_rate 与 MRR
python scripts/build_baseline.py run --evalset data/eval/evalset_oral.jsonl
法条语料：6432 条 / 50 部法 → data/corpus/articles.jsonl
评测集：400 条，平均每条 1.62 个标准法条 → data/eval/evalset.jsonl
语料 6432 条 / 查询 400 条，模型 BAAI/bge-small-zh-v1.5
hit_rate@5 = 0.7975　MRR = 0.6538　未命中 81 条 → data/eval/baseline.json

两个数各管什么

指标算什么什么时候盯它
hit_rate@k标准法条有没有进前 k 条。进了就算对，不管排第几验收主指标。它直接对应「用户能不能找到依据」
MRR命中的那条排在第几位，取倒数再平均辅助指标。hit_rate 不动但 MRR 涨，说明排序变好了——也算进步，可以写进报告

还有第三个数容易被漏掉：没命中的那 81 条。跑完把 details 里 hit: false 的挑出来读十来个，你会发现两类：一类是「问法太偏，检索确实抓不到」，另一类更麻烦——「标准答案本身标错了」。第二类要先修考卷，不然后面所有对比都在这条错标上打转。

基线的完整写法只有数字不够，要连四个条件一起记：哪个向量模型、哪一版语料（多少条）、top_k 取几、考卷是哪一版。四样里换一样，这个数就不可比——不是提升，是换了一把尺子。
基线的意义是「不许事后改口」。训完发现只提升了 2 个点，很想把验收线从 85% 调到 80%——这一步一旦做，整个实验就废了。基线加上验收线，必须在开训前写进需求卡，训完只许对着勾。
这一章钉住了三件事
  • 钉住了：基线 = 不微调时这套题的分，训前必须跑出来并留档
  • 不这么做会：训完只能说「感觉好一点」，评审时被问「好了多少」只能沉默
  • 下次遇到同类问题，先看：这个基线是哪一版语料、哪个模型、top 几跑出来的——条件不全就不能比
带走基线不是一个数，是一个数加四个条件——少一个条件，这个数就作废。

9小结

结论这一课交出去的是三样东西：一页卡、两份数据、一个数。三样都在磁盘上，训练才不是盲训。
交付物落在哪验收看什么
需求卡需求卡.md 放仓库根成功标准能被翻译成指标名 + 方向 + 底线
训练集 + 验证集data/sft/每条都能过 tokenizer 和模板不报错；猜不出哪条是坏样本
考卷 + 基线data/eval/考卷锁死、基线有数、四个条件都记了

开训前，数据侧九项自检

☐项怎么验
□需求卡写完四块齐，成功标准翻得成指标
□一条样本手拼过print(repr(text)) 出来跟预期一字不差
□模板与基座一致角色标记、特殊 token、结尾符逐项对过
□输入里没有线上看不到的字参考法条、格式标记、人工批注都已清掉
□重复查过问题归一化后无大量重复；答案为模板生成的要单独看
□长度分布统计过有 50 / 95 / 99 分位，cutoff_len 有着落
□泄露检查跑过考卷的题在训练集中一条都没有
□考卷锁死sha256 记进数据卡，文件只读，带版本号
□基线跑出来了数 + 模型 + 语料版本 + top_k + 考卷版本，五样齐

四条边界，越界就要返工

  • 考卷先于训练。没有考卷和基线就开训，训完拿不出数，等于白跑一轮。
  • 模板先于数据量。模板不对，两万条好的也训不出对的；模板对了，两千条就能见效。
  • 泄露一票否决。考卷的题混进训练集，指标再漂亮也是假的，而且从数字上永远看不出来。
  • 标准答案只来自标注。让被评估的模型自己评分，等于让考生自己改卷。
下一步数据齐了、尺子立了，机器还没动。下一课把这四环落成实物：机器怎么开、依赖怎么装、框架怎么选、脚本怎么摆——目标是一条命令从数据跑到 adapter。
这门课留下的判据
  • 判据一：前四环的结论必须落成文件，没有文件就是没备过
  • 判据二：输入里出现「线上看不到的字」，一律是泄露，不是特征
  • 判据三：考卷要独立、贴分布、可判；改写只动题面不动答案
  • 判据四：基线是一个数加四个条件，缺一个就不可比
带走先把三个文件备齐、把基线跑出来——训练是后面的事，准备才是这一课的正题。
