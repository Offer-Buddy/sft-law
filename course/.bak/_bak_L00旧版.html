微调不是喂知识，是调习惯

你问「老板让我天天加班不给钱」，它给你讲劳动法概论；你要它照着法条说话，它偏写成科普。这一课把七个绕不开的问题一次说清——它改什么、什么时候用、跟 RAG 怎么分工、要认哪些词、走哪几步、在哪台机器上跑。

1它只动「怎么说」，不动「知道什么」

一个基座模型是这么长出来的：先拿几万亿字的文本硬灌，让它反复做同一道题——下一个字该是什么。灌完之后它确实会说话了，但只会说它见过的样子。你问劳动争议，它给你写一段四平八稳的科普。

这时候有两条路：要么继续往它脑子里塞知识（继续预训练，贵到离谱），要么告诉它「在这个场合，话该这么说」。后者就是微调。

判据微调改的是输出的分布，不是知识库。你没法靠微调让模型凭空知道上周刚发的文件——那是知识，得靠检索。但你能让它从此都按「第一条、第二条」的格式答。

一句话记住：微调是给模型做岗前培训，不是给它发新教材。

岗前培训这个词很关键。培训完它还是那个人，只是在这个岗位上，说话方式、用词、办事流程变了。它没多读一本书，但开口就是行话。

这一章钉住了三件事
  • 钉住了：预训练给「会说话」，微调给「会按这个场合说话」，对齐给「什么不该说」，三件事别混
  • 不这么做会：把新政策当成微调目标，训完模型还是一问三不知——几千条样本装不进一条新规定
  • 下次遇到同类问题，先问自己：我要的是「它知道」，还是「它会说」
带走微调改的是「怎么说」，不是「知道什么」。要它知道新事，找检索；要它换个说法，才找微调。

2什么时候值得动这一刀

微调不是万能药，也不便宜。判断标准只有一条：问题出在「不知道」，还是「不会说」。

你遇到的现象真正缺的是该动哪个
问新政策，它答不上，或者答的是旧版知识检索，不是微调
要求引用原文，它张口就编一句可溯源检索 + 引用约束
每次写成一整篇小作文，你要的是三条要点格式先试 prompt，不行再微调
大白话问，它答得文绉绉，检索还命不中语体微调（本项目就是这一条）
7B 达不到 70B 的效果，但成本扛不住能力密度微调，把大模型的手艺教给小模型
数据不能出内网部署约束私有化 + 微调，手段之一

前两行是知识问题，微调解决不了。中间两行是行为问题，微调最拿手。最后两行是工程约束，微调只是手段之一，不是唯一解。

三种情况，先别急着微调
只差一点表达
先改 prompt。改三轮还不行再考虑微调——改 prompt 五分钟，微调五小时，性价比差两个数量级。
样本不到三百条
先攒数据。这个量级训出来的东西，学的主要是噪声，不是规律。
格式与语体
这是微调的强项。几十条高质量样本就能看出方向，一两千条就能稳定复现。
过关判据：拿你手上任何一个需求，能用一句话说清「这是行为问题还是知识问题」，并且说出理由——说得出，这一章就过了。
这一章钉住了三件事
  • 钉住了：知识问题归检索，行为问题归微调，表达小毛病先归 prompt
  • 不这么做会：拿微调去补知识，几千条样本教不会它一条新政策，钱和时间一起打水漂
  • 下次遇到同类问题，先看：这个错，是它没看过，还是它看过了但说错格式
带走问题是「它不知道」就上检索，是「它不会说」才上微调。这一条判错，后面全是白工。

3和 RAG 的分工：一个开卷，一个改口音

RAG 和微调老被摆成二选一，其实它们动的是两个完全不同的地方。

RAG（检索增强）微调（SFT / LoRA）
解决什么模型不知道、知识会过期说话方式不对、格式不统一
要准备文档库 + 切片 + 向量索引几百到几千条「输入 → 期望输出」
更新成本改文档、重建索引，分钟级重训一轮，小时级
能否溯源能，答案可以指回原文档不能，知识压进权重就说不清出处
出错怎么查看检索命中没命中看训练样本对不对
典型翻车检索到了，模型没用格式学会了，知识学歪了
组合真实系统里两个都用：先用微调把「大白话 → 法条语体」这个转换练出来（本项目就干这个），再用 RAG 把法条找出来。微调负责让问题变得可检索，RAG 负责给出依据。

顺序也有讲究。本项目先微调、后检索——因为检索的前提是「问题本身得写成像法条的样子」，这一步不解决，后面检索再强也白搭：一句口语和一整条法条，字面上几乎零重叠。

这一章钉住了三件事
  • 钉住了：RAG 管素材、能溯源；微调管表达、不能溯源
  • 不这么做会：指望微调记住会变的知识，政策一更新就得整锅重训
  • 下次遇到同类问题，先看：这个错误，换一份资料能不能修好？能，就是 RAG 的活
带走RAG 决定它能看见什么，微调决定它会怎么反应。两个都缺时，先补那个让系统跑不起来的。

4十几个词，够用了

微调的文档一打开全是缩写。这一节只做一件事：把最常撞见的词，每个配一句人话。看完不用记住，知道去哪查就行。

术语一句人话细讲
基座模型还没被教过的那个原始模型，一切微调都从它出发L01
参数量 1.7B17 亿个可调的数字。B 就是十亿L01
token模型眼里的「字」。一个汉字约 1 个，一个英文词常常拆成两三个L02
训练集 / 验证集前者用来学，后者留着验它是不是在死记硬背L04
epoch把训练集从头到尾过一遍叫一个。通常 2–3 遍就够L02
batch size一次喂几条样本。喂得多显存吃紧，喂得少训得慢L02
step喂完一个 batch 算一步。1000 条样本、batch 8，一个 epoch 就是 125 步L02
学习率每步改多大。太大炸，太小等于没学L02
loss当前「错得有多离谱」的分数。训练就是把这条线压下去L02
过拟合训练集上越来越好，换新题就崩。像只背答案不理解L06
灾难性遗忘学新本事把旧本事忘了，连常识都可能丢L12
LoRA / adapter不动原模型，只在旁边挂一小块可训练的参数L03
量化 4bit把权重从 16 位压到 4 位，显存降到四分之一，精度掉一点点L03
OOM显存不够，程序直接被系统杀掉。中文叫「爆显存」L03

这些词不用背。你在训练日志里撞见它们的时候，回来查一眼就行——真正要条件反射记住的只有一句：loss 在降 = 在学；loss 不降或乱跳 = 参数或数据有问题。

这一章钉住了三件事
  • 钉住了：batch 决定显存，epoch 决定过几遍，学习率决定每步多大，loss 是唯一的仪表盘
  • 不这么做会：把「loss 不降」当成模型不行，其实是学习率小了两个数量级
  • 下次遇到同类问题，先看：loss 曲线，再看数据，最后才怀疑模型
带走术语不用背，撞见再查。唯一要条件反射的是 loss 的三种形态：降下去、不降、先降后炸。

5六步，其中两步决定成败

一次微调从头到尾就六步。新手以为难在训练，其实训练是里面最标准的一步——脚本一跑，剩下交给时间。

为什么是这两步
第 ① 步 定任务
输入是什么、输出长什么样、怎么算对。这一步含糊，训出来的东西没法验收——你连「好」都定义不了。
第 ⑥ 步 评测
拿一套固定的题，微调前后各跑一遍。没有这个对比，「效果变好了」只是感觉。
中间四步
备数据、选基座、选方法、训练，都有成熟工具和标准做法，照着走就行。

第 ② 步「备数据」最容易被低估。一个大概的量级：几百条能看出方向，一两千条能稳定复现，上万条才谈得上行业水准。但数据不是越多越好，是越准越好——一千条干净样本胜过一万条噪声。

一个常见的坑：训练 loss 一路降到 0.1，换新题却一塌糊涂。成因是样本里同一类问题反复出现，模型把答案背下来了。解法是留 10% 数据不参与训练，只用来看它会不会做新题。

评测不过就回第 ② 步，这个回流是常态，不是失败。反过来，第一轮就全面达标才要警惕——多半是评测集太简单，或者训练集里漏了同类题。

这一章钉住了三件事
  • 钉住了：定任务和评测决定成败，中间四步照标准做，训练是最不操心的那一步
  • 不这么做会：没有固定考卷，改了十版也不知道哪版更好，最后靠感觉挑一个
  • 下次遇到同类问题，先看：我有没有一套「微调前后都能跑」的题
带走六步里训练最标准，定任务和评测最难。跳过评测的微调，等于闭着眼睛改代码。

6在哪跑：先看你手上有什么

微调要两样东西：一个框架（写代码那层）和一台有显卡的机器（算力那层）。两样都可以零成本起步。

框架一句话适合谁
transformers + peft + trlHuggingFace 官方三件套，最灵活，也最啰嗦要改训练逻辑的人
LLaMA-Factory一条命令起 WebUI，点几下就开始训，支持上百个模型想先跑通、不想写代码的人
ms-swift魔搭官方，和魔搭的模型库、Notebook 打通主要在魔搭上做的人
Unsloth主打快和省显存，同一张卡能训更大的模型显存紧张、又不想降配置的人

不想写代码的，装完 LLaMA-Factory 只要一行：

终端
# 装完之后，一条命令起图形界面
llamafactory-cli webui

浏览器会自动打开一个本地页面，选模型、传数据、点「开始」，训练就跑了。第一轮建议就用它——先把流程走通，再回头理解每一步在干什么。

在哪跑有什么花多少
自己电脑（没独显）只能跑 0.5B 级别的演示，1.7B 会慢到无法忍受0
自己电脑（4090 24G）1.7B 的 LoRA 很舒服，7B 的 QLoRA 也能挤进去已有硬件
魔搭 Notebook免费 GPU（A10 24G），环境预装好，打开网页就能跑0，额度用完为止
AutoDL按小时租，4090 24G 约 2 元/时，用完就关跑一轮十几块
阿里云 PAI / 腾讯云企业级，稳定、有发票、有 SLA贵一个量级

价格是量级不是报价。2026 年 11 月 AutoDL 官网标价：4090 24G 1.98 元/时，3090 24G 1.32 元/时；活动价、会员价、地区节点都会有差异，下单前看控制台实时报价。

建议没卡的人别在本地折腾环境。装驱动、装 CUDA、装对版本的 torch——这一套能耗掉一整天，而且学不到微调的任何东西。直接上魔搭的免费 Notebook，环境是预装好的，打开网页就能跑。
本地最常见的翻车：torch.cuda.is_available() 返回 False。成因是驱动版本低于 CUDA 要求，或者 pip 装成了 CPU 版 torch。解法先跑 nvidia-smi 看驱动版本，对不上就别修了——换云端，十分钟能开始，比修环境快得多。
这一章钉住了三件事
  • 钉住了：框架决定写多少代码，平台决定花多少钱，两样都能零成本起步
  • 不这么做会：在本地跟 CUDA 版本较劲两天，微调还没开始就放弃了
  • 下次遇到同类问题，先看：nvidia-smi 能不能跑通，跑不通就上云
带走框架选「能最快跑通的那个」，平台选「现在就有卡的那个」。环境折腾超过一小时，就该换方案。

7小结

这一课没教你训任何模型，只把七个问题摆正了位置。摆正之后，后面十五课各自落在哪一段，你心里应该有数了。

层常见的以为实际是
微调 vs 知识微调能让模型知道新政策不能。知识归检索，微调改的是表达
微调 vs prompt效果不好就该微调先改 prompt，改三轮不动再微调
难在哪难在训练那一步难在定任务和评测，训练是最标准的
门槛得有显卡才能学免费额度就够跑通一轮

四条边界，越过就该停

  • 样本不到三百条，别开训。学到的多半是噪声，不是规律。
  • 没有固定评测集，别开训。训完也不知道好不好，只能靠感觉。
  • 分不清知识问题还是行为问题，别开训。大概率是检索的活，微调白做。
  • 指望微调让模型「更聪明」，别开训。它改表达方式，不改能力上限。

四条自检，能独立验证

现在就能自己判
判据一
能用一句话说出「我这是行为问题还是知识问题」，并给出理由。
判据二
能说清微调、RAG、prompt 三者各管什么，以及为什么微调不能溯源。
判据三
看到 loss 曲线，能判断它是在学、没学、还是炸了。
判据四
能说出自己下一步在哪台机器、用哪个框架跑，以及大概花多少钱。
下一步下一课进项目：这个「大白话 → 法条语体」的活儿，为什么非微调不可——四条替代路线，会一条条被排掉。
带走微调是手段不是目的。先判断问题是「不知道」还是「不会说」，再决定动哪把刀。
