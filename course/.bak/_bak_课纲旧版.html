课程定位

不教「怎么训」，教「怎么判断该不该训、训完有没有变好」

面向对象零基础学员。会写最基础的 Python、能照着改脚本、看得懂报错即可，不需要机器学习背景，不需要推导公式
主线项目sft-law —— 独立的微调工程，不含检索系统与业务系统。自带 23,331 条训练对、6,432 条法条语料（50 部法）、2,563 道遗忘检测题。产出只有一个：一个能把大白话翻成法条语体的适配器
技术主线QLoRA（4bit 加载 + LoRA 微调）+ Qwen3-1.7B-Instruct + AutoDL 租卡（4090 24G）
训练目标训练一个 HyDE 翻译器：输入一句生活语言的法律问题，输出一段适合向量检索的法条语体文本
最终交付一个能接进任意法律 RAG 检索前面、有评测数据支撑、能说清「为什么这样调」的适配器
为什么主线选 HyDE 而不是法律问答：HyDE 有可量化的检索指标，学员能亲眼看到微调让检索变好了；法律问答训完只能自嗨——答得好不好没法量化，而且这层能力下游系统本来就由大模型负责，小模型训了也接不进去。
开课前必须知道的三件事：脚本是齐的，但 训练集还没造（原始素材在 data/raw/，23,331 条可用，但不能直接喂给模型，得先抽成「问题 → 法条」对）、GPU 没有（本机 torch.cuda.is_available() 为 False）、基线还没有（要先跑 L02 造尺子、量出基线）。这三件正是课程要解决的。

前导 · 微调全景

L00
L00

微调全景：它改什么、什么时候用、在哪跑

45′
目标
零基础的人先把地图建起来：微调到底改什么、什么情况下才值得动、跟 RAG 怎么分工、要认哪些词、在哪台机器上能跑。这一节不训任何模型，只解决「我知道这件事是怎么回事、该不该做」
内容
① 改什么　预训练给「会说话」，微调给「会按这个场合说话」，对齐给「什么不该说」。微调动的是表达不是知识，所以新政策塞不进去
② 什么时候用　一条判据：问题是「不知道」还是「不会说」。不知道归检索，不会说才归微调，表达小毛病先归 prompt。附六行现象对照表与三条「先别急着微调」
③ 与 RAG 的分工　一个开卷、一个改口音。六维对比：解决什么、要准备什么、更新成本、能否溯源、出错怎么查、典型翻车。结论是两个都要，本项目先微调改语体、再检索找法条
④ 术语　十四个词各配一句人话：基座、参数量、token、epoch、batch、step、学习率、loss、过拟合、灾难性遗忘、LoRA、量化、OOM，每个标了细讲在哪一节
⑤ 六步流程　定任务 → 备数据 → 选基座 → 选方法 → 训练 → 评测，评测不过回流到备数据。真正决定成败的是第一步和第六步，训练反而最标准
⑥ 在哪跑　四套框架（官方三件套 / LLaMA-Factory / ms-swift / Unsloth）+ 三种机器（自己电脑 / 魔搭免费 Notebook / AutoDL 按小时租）
节奏
讲 30 · 练 10 · 验收 5（切片见下方）
练习
拿自己手上任何一个需求，填一行判断表：现象 / 真正缺的是知识还是行为 / 该微调还是该检索 / 为什么。再跑一次 nvidia-smi，把显卡型号和显存记下来，对照三种机器选一条起步路线
验收
口述一分钟：我这个需求为什么该走微调（或该走检索），下一步在哪台机器、用哪个框架跑，大概花多少钱。三问答不全，说明地图还没建立
45 分钟切片（讲 30 / 练 10 / 验收 5）：0–4 从一次失败的检索开场　·　4–12 三层能力与「改表达不改知识」　·　12–19 判断该不该：知识问题还是行为问题　·　19–27 与 RAG 的分工 + 六维对比　·　27–32 十四个术语速览（不逐个讲，标好去哪个节细看）　·　32–38 六步流程与两处关键　·　38–40 框架与平台选型　·　40–45 练习与 Checkpoint
这一节的作用是防止后面十五节白学：判错了「该不该微调」，后面每一步都在给一个错误的目标打工。

模块一 · 定位与决策

L01–L03
三节课是一条收窄的线，别讲重：L01 给全局账（背景、问题、数据、路线，点到为止）→ L02 把问题量出来（造口语评测集、建最小检索、跑出这个项目自己的基线）→ L03 给工具（全参 / LoRA / QLoRA 选哪个、为什么）。
L01

项目整体介绍：背景、问题、数据与解决路线

45′
目标
开篇只讲五件事：这个系统在做什么、它卡在哪、为什么非微调不可、手上有什么数据、这 15 节课怎么走。学员下课时必须知道「我在修什么、拿什么修」
内容
① 背景　sft-law 是一个独立的微调工程，范围只有一格：把一句生活语言的法律问题，翻成一段法条语体文本，交给检索。不做路由、不做工具调用、不做回答生成。家底：23,331 条训练对、6,432 条法条（50 部法）、2,563 道遗忘检测题、79,692 条书面语问答
② 问题　用户说「老板让我天天加班不给钱」，法条写「延长工作时间支付百分之一百五十的工资报酬」——两句话字面零重叠，检索命中不了。业界已有解法 HyDE，但通行实现是每次检索都调一次云端大模型：慢、贵、断网即废、版本锁不住
③ 为什么只能微调　规则与同义词穷举不完；Prompt 改写仍要调大模型，慢和贵原封不动；增加法条不解决问题（6,432 条已在库，缺的不是知识）；换更大 embedding 只是让两句话变近，不能让一句话变成另一句。四条排掉，剩微调
④ 数据有什么　四类，用途完全不同：训练对 Triplet 23,331 条（问题 + 对应法条，100% 可解析）；法条语料 去重后 6,432 条 / 50 部法，就是检索要命中的目标库；遗忘检测 DISC-Law-Eval 2,563 题；考卷 暂时没有——这是一个必须当面说清的缺口：DISC-Law 的问题本身是书面语（平均 68.6 字、带「民事责任」这类术语），拿它测检索会虚高，口语评测集要在 L02 现造。另外两点：① 这个数据集没有随附检索评测集，DISC-Law-Eval 考的是司法考试选择题，没有「该命中哪条法条」这一列；② 数据偏商事金融——被引最多的是民法典、刑法、刑诉、民诉，紧跟着海商法、证券法、公司法，与日常咨询错配，训练前必须往日常场景拉
⑤ 怎么解决　造数据（L4–L7）→ 租卡训练（L8–L11）→ 评测（L12–L13）→ 接入下游（L14–L15），一张路线图把 15 节课钉在墙上
节奏
讲 28 · 练 12 · 验收 5（切片见下方）
练习
填一张「项目现状四格表」——背景 / 问题 / 数据 / 方案，每格用自己的话写两句，不许抄课件；顺手跑 torch.cuda.is_available()，打开 data/raw/ 数一眼有什么、没什么
验收
对着四格表讲 1 分钟：这个系统缺什么、为什么缺、这 15 节课打算怎么补。讲不顺，说明地图没建立
45 分钟切片（讲 28 / 练 12 / 验收 5）：0–3 开场与交付物　·　3–9 背景与系统全景（一张图）　·　9–16 问题：一次检索为什么失败 + HyDE 的四笔账　·　16–21 排除四条替代方案　·　21–26 数据账：三源清单 + 偏科问题　·　26–28 路线图，把 15 节课串成一条线　·　28–40 练习：填四格表　·　40–45 Checkpoint
这节课不解决任何技术问题，只解决一件事：让学员知道自己站在哪、要往哪走。
L02

造一把尺子，量出真实基线

45′
目标
把 L01 说的「听不懂人话」变成一个数字和一个文件。难点不在跑，在先有尺子——这个项目没有现成考卷，所以这一节要连评测集一起造。产出的 baseline.json 是 L13 做 A/B 对比的唯一对照组，没有它，「提升了多少」全是空话
内容
① 为什么不能直接拿 Triplet 的问题当考卷　抽一条真实样本摆出来：「李先生在路上遇到一位昏倒的老人，他自愿进行紧急救助……」——书面语、带术语、贴着法条写，而真实用户说的是「我救了人把人弄伤了要不要赔」。已实测：同一批 40 条，书面语 hit_rate 0.775、首位命中 87%；改写成口语后 0.725、首位命中 66%。掉得最狠的不是命中率，是排序
② 造尺子三步　抽 400 条 Triplet → 把问题改写成口语（标注原样保留，法条不变）→ 人工抽查 10%。改写会引入噪声，但标注不用重标，这是唯一不花钱又能量出口语水平的办法
③ 只讲一个指标　hit_rate@5 = 前 5 条里有没有一条对上。不讲 MRR 公式、不讲 precision / recall，这三个留到 L13
④ 建最小检索　6,432 条法条做语料，embedding 编码，余弦相似度取 top-5。不用数据库——一个 numpy 数组就够，六千多条法条乘四百条问题的矩阵，几秒钟算完
⑤ 跑第一次并归因　得到基线数字，翻未命中样本，分三类：知识缺失（库里确实没有）／说法不同（库里有，但用户不这么讲）／标注问题（reference 本身就对不上）。这一类必须留——实测 40 条里有 7 条两种问法都失败，翻标注才发现是标错了（家暴题标到立法目的条款、怀孕拒录标到村委会义务条款），不揪出来就会拿错的靶子去调模型
节奏
讲 10 · 练 28 · 验收 7（切片见下方）
练习
跑通造尺子三步；建索引跑出 hit_rate；存 baseline.json；挑 10 条未命中填归因表（问题 / 应命中 / 实际命中 / 失败类型 / 一句话判断）
验收
能报出自己的 hit_rate、失败条数、其中多少条属于「说法不同」，并交出 baseline.json。说不出数字 = 这节课白上
45 分钟切片（讲 10 / 练 28 / 验收 7）：0–4 承接 L01，抛问题「到底差多少」　·　4–10 为什么不能直接拿书面语测　·　10–18 造尺子：抽 400 条 + 改写 + 抽查　·　18–30 建索引、跑出 hit_rate　·　30–40 翻失败样本、归因填表　·　40–45 存基线 + Checkpoint
环境风险要提前兜住：这一节故意不依赖数据库——法条库只有 6,432 条，用 sentence-transformers 编码后存成 numpy 数组，余弦相似度直接算。装一个包就能跑完，不会卡在起 Postgres 上。真正要紧的是 embedding 模型第一次下载（几百 MB），课前统一拉好。
定性靠讲，定量靠跑。「首位命中只有 66%」比「你检索不太准」有力一百倍。
L03

选型：先选方法，再选框架

45′
目标
知道选哪个，更知道为什么不能选别的；两个维度分清楚——方法决定跑不跑得动，框架决定写多少代码
内容
① 方法谱系（20 分钟）　参数谱系（改 100% → 改 0.1%）；全参的代价：7B fp16 权重 15G + 梯度 + 优化器状态 ≈ 60G 起步，4090 跑不动，且有灾难性遗忘；Adapter / Prefix / P-Tuning 已被取代，带过；LoRA 讲透；QLoRA 只改加载精度不改训练逻辑；DPO / RLHF 属对齐层，法律场景慎用
② 框架选型（5 分钟，只看一张表）　主线用项目脚本那套 transformers + peft + trl——loss 怎么算的看得见，出问题能查；LLaMA-Factory 是 YAML 一条命令、批量跑多种模型快，但黑盒，0 基础学员出问题查不了；Unsloth 省显存 40%+，卡实在不够时作后路；ms-swift 国产、Qwen 系友好。结论一句话：跟项目脚本走，其余三个知道名字和适用场景就够
节奏
讲 25 · 练 12 · 验收 8（切片见下方）
练习
算一笔显存账：fp16 加载 vs 4bit 加载，同样 4090 24G 分别能开多大 batch；再对着框架表，给自己一句话选型理由
验收
能说出「为什么选 QLoRA」，且知道全参不是更高级、是卡跑不动；能回答「为什么不直接用 LLaMA-Factory」
45 分钟切片（讲 25 / 练 12 / 验收 8）：0–4 全参为什么贵、为什么忘　·　4–6 Adapter / Prefix / P-Tuning 带过　·　6–17 LoRA + QLoRA 讲透　·　17–22 框架选型决策表　·　22–25 DPO / RLHF 带过　·　25–37 练：算显存账　·　37–45 验收
为什么框架只给 5 分钟：框架会换版本，原理不会。LoRA 永远是 r / alpha / target_modules 三个数，换成哪个框架都是这三个数。教框架是把学员绑在一个工具上，教参数才是教能力。学员在外面刷到 LLaMA-Factory 教程会回来问，这张表就是答案。
一句话记牢：LoRA 和 QLoRA 不是两个选项，是一个选项的两种加载方式；框架也不是选型难题，是跟着项目脚本走就行。

L06

法律场景清洗与校验

45′
目标
这是法律微调和通用微调最大的区别所在
内容
五道关卡：法条编号是否存在、是否现行有效、是否混入建议体、长度分布是否合理、问题是否重复；法条号回查方法（正则抽「第 X 条」对照从 reference 抽出的 6,432 条法条）；时效对照最新校验报告
节奏
讲 8 · 练 27 · 验收 10
练习
写五段校验函数，跑全量，统计每道关卡的淘汰率
验收
产出淘汰率报告，能解释「为什么法律场景不能直接用公开数据集」
关键细节：训练脚本用 response-only loss（labels = [-100] * prompt_len + input_ids[prompt_len:]），样本超长被截断时，丢的是答案的后半段甚至整段。所以长度必须卡在数据侧，不能指望训练脚本兜底。
L07

切分、版本化与数据卡

45′
目标

内容
train 8 : val 1 : test 1；口语评测集只进 val/test，训练集全靠合成；数据卡要写清来源、条数、清洗规则、已知缺陷、生成时间
节奏
讲 8 · 练 27 · 验收 10
练习
切分并落盘；写一页数据卡；给文件打版本号（如 hyde_v1_20261113）
验收
拿到数据卡就能复现出同一份训练集
最致命的一个坑：把评测集混进训练集，指标会虚高到 0.9 以上，上线全崩。真实数据只做验证，是硬规矩。

L09

LoRA 原理与显存账

45′
目标
不推导公式，也能说清「为什么这样能省」
内容
用「书改不动就贴便利贴」建立直觉 → 拆结构（W 冻结 + A×B 可训练）→ 回答「为什么窄的就够」（调音量不用重造音响）→ r / alpha / dropout 三个旋钮 → 4bit 是「毫米尺换厘米尺」→ 显存账（fp16 约 15G vs 4bit 约 4.5G）

验收

数学恐惧先拆掉：这门课一个公式都不用推，你只要会看三张图——loss 曲线、显存占用、评测对比表。

45′
目标

内容
四类高频故障：OOM（降 max_length / 降 batch / 开 4bit / 加梯度累积）、loss 不降（lr 太小、mask 没生效、数据格式错）、过拟合（epoch 太多、r 太大、数据重复）、灾难性遗忘（lr 太大、数据太窄）；每个故障给「现象 → 判断 → 动作」三段式

三条贯穿全课的主线

这三条线在每节课都会出现一次，不要当成额外内容

一、跨机器工作流

Windows 造数据 → 上传 AutoDL → Linux 训练 → 下载 adapter → 拷回 Windows 项目 → 改 .env 接入。

为什么必须画出来：项目脚本里全是 macOS 绝对路径，本地是 Windows、训练机是 Linux，同一份脚本要改三次路径。L08 开头画一次，L15 收尾时回看一次。

二、理论图卡

15 张 16:9 图卡，每张一个概念，配「一句话比喻 + 一个 30 秒实验」。

  • 单次理论块不超过 8 分钟
  • 每张图卡后面必须跟一个可动手的观察
  • 公式一律不上图卡，术语给中英对照

三、评测闭环

任何一次参数改动，都要有指标支撑，不许「我感觉变好了」。

从 L02 把基线钉死（自己造的口语评测集 + baseline.json）开始，每改一次训练配置就重跑一次对比表。到 L15 时，学员手里应该是一串数字从基线往上走，而不是一堆印象。

教学规则

规则原因
单次理论块 ≤ 8 分钟超过 8 分钟，零基础学员注意力必然掉
每课时前 3 分钟回扣上节微调概念是链式的，断一节后面全懵
每 3 课时做一次串联L03 / L07 / L11 / L14 末尾，把前面的概念拉成一条线
公式一律不写，术语给中英对照不写公式，但 epoch、batch size 这些会出现在报错里
每节课必须有 Checkpoint没有验收点的课，学员会以为自己懂了
