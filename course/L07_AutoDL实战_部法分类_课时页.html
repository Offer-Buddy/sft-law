1这一课做什么

结论同一份数据、同一个基座、同一条分类任务，只换平台与框架——用来对照看清「什么是任务、什么是环境」。

L06 在魔搭用 ms-swift 跑通了。这一课把同样的活搬到 AutoDL，用 LLaMA-Factory 再跑一遍。

为什么值得再跑一遍：只有换过一次环境，你才知道哪些步骤是任务本身的、哪些只是平台的习惯。

框架ms-swift，命令行参数LLaMA-Factory，yaml 配置文件
数据字段query / responseinstruction / output + 注册进 dataset_info
数据放哪/mnt/workspace//root/autodl-tmp/（数据盘）
计费免费额度，按小时扣按小时付费，关机不计费
数据量18,338 条18,338 条（同一条没变）
  • 任务、数据、基座三样不变，变的只有镜像、数据格式、配置形态。
  • 换一遍平台的价值是「分清哪些步骤属于任务」，不是多训一个模型。
  • AutoDL 按小时计费，跑完要关机，否则一直在扣。
一句话带走换环境时先问：这一步是任务要求，还是这个平台的习惯？分不清就会把平台习惯当成知识背下来。

3开机选镜像

结论选一个预装 LLaMA-Factory 的社区镜像，省掉整套环境安装——这是 AutoDL 相对魔搭最大的省事点。

创建实例时在「镜像」一栏选 社区镜像，搜 LLaMA-Factory，挑一个更新日期近的。

开机后进 JupyterLab，先确认框架在不在：

llamafactory-cli version
ls /root/autodl-tmp
$ llamafactory-cli version
LLaMA-Factory, version 0.9.x
$ ls /root/autodl-tmp
（空目录）
镜像里自带的目录在哪大多数 LLaMA-Factory 镜像把代码放在 /root/LLaMA-Factory，data/ 是它的数据目录。先用 find / -maxdepth 3 -name "LLaMA-Factory" -type d 2>/dev/null 定位一下，别硬猜。
镜像选错版本太老的镜像里 llamafactory-cli 可能叫 python src/train.py，参数名也不一样（evaluation_strategy vs eval_strategy）。跑不通先 llamafactory-cli version 看一眼，版本太旧就换镜像，别在旧版本上改参数。
这一步的判据llamafactory-cli version 能打出 0.9 以上的版本号。打不出来说明镜像不对，后面每个命令都会失败。
  • 社区镜像自带框架，省掉 pip 装依赖这一步。
  • 代码目录一般在 /root/LLaMA-Factory，用 find 定位别硬猜。
  • 版本太旧就换镜像，不要在旧版本上迁就参数。
一句话带走现成镜像省的是时间，不是理解——它把「装了什么」藏起来了，你得知道里面有什么才算会用。

4准备数据

结论转成 instruction/output 两字段，放进 data/，再在 dataset_info.json 里注册一行——三步缺一不可。

本地先导出（L06 已经跑过这条命令，产物是一样的）：

python scripts/export_platform_data.py
ls data/cls/export/llamafactory/

LLaMA-Factory 认的是另一套字段名。同一个样本，两个平台的写法对照：

ms-swift 吃的：query / response
{"query": "请判断…问题：小王是…", "response": "个人独资企业法"}
字段名固定，框架按这个名字找。
LLaMA-Factory 吃的：instruction / output
{"instruction": "请判断…问题：小王是…", "input": "", "output": "个人独资企业法"}
多一个空 input，是 alpaca 格式的固定位。

上传并注册

把两个 jsonl 传到 /root/autodl-tmp/LLaMA-Factory/data/，然后在同目录的 dataset_info.json 里加两行：

"cls_law": {
  "file_name": "cls_train.jsonl",
  "columns": { "prompt": "instruction", "response": "output" }
},
"cls_law_val": {
  "file_name": "cls_val.jsonl",
  "columns": { "prompt": "instruction", "response": "output" }
}
columns 这一行在干什么告诉框架「我文件里 instruction 这个字段，就是你要的 prompt」。字段名和框架默认一致时可以不写，但写上更保险——换个数据集字段名不一样时，改这一行就行，不用动文件。

注册完验一眼，注册名和文件都在：

# 行数 + 字段名 + 注册是否生效
wc -l /root/autodl-tmp/LLaMA-Factory/data/cls_*.jsonl
head -n 1 /root/autodl-tmp/LLaMA-Factory/data/cls_train.jsonl
python -c "import json;d=json.load(open('/root/autodl-tmp/LLaMA-Factory/data/dataset_info.json'));print(list(d))"
$ wc -l .../cls_*.jsonl
 18338 .../cls_train.jsonl
  2292 .../cls_val.jsonl
$ python -c "...print(list(d))"
['alpaca_...', 'cls_law', 'cls_law_val', ...]
三处最容易错的地方① 文件放在 data/ 之外（file_name 是相对 data/ 的）；② JSON 里多一个逗号导致整个文件解析失败，训练会直接报 dataset not found；③ 改了 dataset_info.json 没重启 notebook 进程，读的还是旧缓存。
  • 两个平台字段名不同，互转只改字段名，不动内容。
  • dataset_info.json 是「注册表」，不注册框架就找不到文件。
  • 文件必须在 data/ 下，file_name 写相对路径。
一句话带走换框架时先看它「认哪些字段名」——数据本身一个字都不用改，改的是映射。

5一个 yaml 起训

结论把 L06 那串命令行参数翻译成一个 yaml，然后 llamafactory-cli train 一条命令起训。

cls_qlora.yaml

### model
model_name_or_path: Qwen/Qwen3-1.7B
trust_remote_code: true

### method
stage: sft
do_train: true
finetuning_type: lora
lora_rank: 16
lora_alpha: 32
lora_target: all

### dataset
dataset: cls_law
eval_dataset: cls_law_val
template: qwen3
cutoff_len: 512
preprocessing_num_workers: 8

### output
output_dir: /root/autodl-tmp/saves/qwen3-1.7b/cls
logging_steps: 20
save_steps: 200
eval_steps: 200
eval_strategy: steps
save_total_limit: 2
plot_loss: true

### train
per_device_train_batch_size: 8
gradient_accumulation_steps: 2
learning_rate: 2.0e-4
num_train_epochs: 2.0
lr_scheduler_type: cosine
warmup_ratio: 0.05
bf16: true

### QLoRA：两条一起才叫 QLoRA
quantization_bit: 4
quantization_method: bnb

### 加速
use_unsloth: true

同一组参数，两个框架怎么对应

要调的东西ms-swift 写法LLaMA-Factory 写法
训练数据--dataset 路径.jsonldataset: 注册名
验证数据--val_dataset 路径.jsonleval_dataset: 注册名
QLoRA--quant_bits 4quantization_bit: 4
截断长度--max_length 512cutoff_len: 512
学几轮--num_train_epochs 2num_train_epochs: 2.0
有效 batchbatch × gradient_accumulation_steps同左，名字一样

对完这张表你会发现：参数几乎一一对应，变的只是写法——一个写在命令行，一个写在文件里。

跑起来

cd /root/LLaMA-Factory
llamafactory-cli train cls_qlora.yaml
$ llamafactory-cli train cls_qlora.yaml
trainable params: ~20 M || all params: ~1.7 B || trainable%: ~1.2
{'loss': 3.4, 'grad_norm': 1.1, 'learning_rate': 1.8e-05, 'epoch': 0.04}
{'loss': 1.8, 'grad_norm': 0.9, 'learning_rate': 4.0e-05, 'epoch': 0.17}
{'loss': 0.9, 'grad_norm': 0.6, 'learning_rate': 5.6e-05, 'epoch': 0.35}
{'eval_loss': 0.6, 'eval_accuracy': 0.6, 'epoch': 0.52}
{'loss': 0.4, 'grad_norm': 0.4, 'learning_rate': 3.2e-05, 'epoch': 1.10}
{'eval_loss': 0.3, 'eval_accuracy': 0.8, 'epoch': 1.35}

同样是形态示意：你的数会不一样，盯 eval_accuracy 的走向就行。

Unsloth 与 QLoRA 同时开报错部分镜像里的 Unsloth 版本与 4bit 量化会打架。真撞上报 unsloth 相关错误，把 use_unsloth 那行注掉（前面加 #）再跑——慢一点，但能跑完。
两个必须盯的数trainable% 在 1%~2%（说明只训了补丁），eval_accuracy 在涨（说明还没到该停的点）。两个都对，就等它跑完。
  • yaml 是「参数换了个写法」，内容和命令行版本一一对应。
  • eval_strategy: steps + eval_steps 才让验证准确率定期打印。
  • Unsloth 与 4bit 打架就注掉那行，能跑完比跑得快重要。
一句话带走配置文件不是另一种知识，它只是把命令行参数抄进了文件——看不懂 yaml 时，逐行翻回命令行就懂了。

6看 loss 拿 adapter

结论产物结构和魔搭一模一样，只是路径在数据盘；挑 eval_accuracy 最高那个 checkpoint。
/root/autodl-tmp/saves/qwen3-1.7b/cls/
├── checkpoint-600/
│   ├── adapter_config.json          # LoRA 配置
│   └── adapter_model.safetensors    # 补丁权重，约 40 MB
├── checkpoint-800/
├── training_loss.png                # plot_loss 画出来的曲线
└── trainer_log.jsonl                # 完整记录，含 eval_accuracy

挑 checkpoint 的方法和 L06 一致：在 trainer_log.jsonl 里搜 eval_accuracy，取最高那步。

# 只打包选中的 checkpoint，别整包下载
cd /root/autodl-tmp/saves/qwen3-1.7b/cls
tar -czf cls_adapter.tar.gz checkpoint-800/
存在系统盘上默认 output_dir 若写在 /root/ 下，关机后可能随系统盘一起被释放，白训。所有产出都写进 /root/autodl-tmp/——那是数据盘，关机还在。
  • 产物结构与 ms-swift 完全一致：配置 + 补丁权重 + 日志。
  • 选 checkpoint 看 eval_accuracy，不看最后一个。
  • 所有输出写数据盘，关机才不丢。
一句话带走两个框架产出的东西长得一样——因为 LoRA 的产物本来就只由「补丁」决定，跟谁训的无关。

7验它学会了

结论用同一份 test 集、同一个脚本，跑出与 L06 同口径的数字——这样两平台才可比。

先跑基线，再跑微调后。脚本和评测集都跟 L06 一样：

# 1) 基线
python scripts/eval_cls.py --no-adapter \
  --model Qwen/Qwen3-1.7B \
  --data data/cls/export/test_eval.jsonl --limit 200

# 2) 微调后
python scripts/eval_cls.py \
  --model Qwen/Qwen3-1.7B \
  --adapter /root/autodl-tmp/saves/qwen3-1.7b/cls/checkpoint-800 \
  --data data/cls/export/test_eval.jsonl
关键在「同口径」同一个 test 集、同一个 prompt、同一套 length-normalized 打分。换了一样就不叫对照——数字涨了也说明不了是模型变好还是尺子变松。
指标魔搭（L06）AutoDL（本课）怎么读
accuracy自己填自己填两个平台的差距应在一个点内
macro-F1自己填自己填差很多说明训练没收敛
top-3自己填自己填接近 accuracy 说明很有把握
用时 / 费用约 1 小时 / 免费约 1 小时 / 计时长 × 单价自己算一遍

两个平台训同一个任务、同一份数据，准确率应当非常接近。如果差出好几个点，先怀疑数据或超参不一致，别急着归因到平台。

忘了关 thinking 或没对齐模板手测时用 llamafactory-cli chat 要带 --template qwen3；模板不对，模型输出格式和训练时不一致，准确率会莫名其妙掉一截。
  • 同口径才能对照：同数据、同 prompt、同打分方式。
  • 两平台结果应接近；差很多先查数据与超参，再怀疑平台。
  • 手测也要对齐 template，否则输入格式和训练时不一样。
一句话带走可复现的判据是「别人换台机器跑出同一个数」——差在 0.5 个点以内，说明这条链真的通了。

8小结

结论两条链走完，你手里有两组可比的数字，和一张「什么是任务、什么是环境」的对照表。
层这次动了什么没动的部分
环境层换成 AutoDL 现成镜像，不装依赖GPU 型号一样是 24G
数据层字段名 query/response → instruction/output内容一条没改，还是 18,338 条
配置层命令行参数 → 一个 yaml超参数值逐个对应，一个没变
任务层无50 类分类、QLoRA、max_len 512 全部照旧

两个平台怎么选

不是「哪个更好」，是「什么时候用哪个」
选魔搭预算为零、第一次跑通、只需要验证「这条路行不行」——免费额度够用
选 AutoDL要连跑多次、要长期留环境、要换大模型——按小时付费比等免费额度划算
别做在两个平台间反复搬数据比效果——数据不动、任务不动，效果本来就该一样

三条边界

  • 产出不写数据盘关机后可能一起没，几小时白跑。
  • 不注册 dataset_info 就开训框架找不到文件，报错信息还容易误导你以为是路径问题。
  • 拿两个平台的不同口径比准确率数据集或模板不一样，比出来的差值是假的。

三条自检

每一步都能单独验，不用等全跑完
① 环境llamafactory-cli version 打出 0.9 以上
② 数据注册名在 dataset_info.json 里能查到，wc -l 对得上 18338
③ 结果本课 accuracy 与 L06 相差在 0.5 个点内，超了就回头看数据与模板
下一步两条链都通了，接下来该动「尺子」：把 test 集按部法拆开看，找出小类错在哪、混淆矩阵最亮的是哪一格——那才是调参的起点。
  • 换平台只动三处：镜像、字段名、配置形态；任务与数据不动。
  • 两平台结果应接近，差得远先查数据与模板。
  • 按小时计费的机器，跑完就关，产出写数据盘。
带走跑通两条链不算本事，能说清「哪一步换平台要改、哪一步不用改」才算真懂——那三处改完，剩下的原件照搬。
