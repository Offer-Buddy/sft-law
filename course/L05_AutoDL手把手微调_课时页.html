1这一课：把 L04 的链，搬到 AutoDL 重跑一遍

结论任务没变，还是「口语 → 法条语体」的 HyDE 改写；变的是平台和框架——L04 魔搭配 ms-swift，这一课 AutoDL 配 LLaMA-Factory + Unsloth。

和 L04 魔搭比，这四点不一样

维度L04 · 魔搭L05 · AutoDL
平台免费 36 小时 A10租 4090 24G，约 1.9 元/时
框架ms-swift，一条 swift sftLLaMA-Factory，一个 yaml + 一条 train
数据吃法query/response 直接吃instruction/output，还要在 dataset_info.json 注册
加速无（镜像预装 torch/CUDA）Unsloth，一条 use_unsloth: true
下模型魔搭内网直下，几分钟走 HF 慢，要设镜像或切魔搭
这一章钉住了三件事
  • 钉住了：任务没变，变的是平台（魔搭→AutoDL）和框架（ms-swift→LLaMA-Factory）
  • 不这么做会：把 L04 的命令原样搬到 AutoDL，发现 swift sft 根本不在
  • 下次遇到同类问题，先问：这个框架吃哪种数据格式、命令入口是什么
带走换平台先认三样：命令入口、数据格式、下载源——这三样对不上，命令搬过去也白搭。

2注册充值租卡：手机号 + 充 10 元

结论注册用手机号；实名后充最小额度，租一张 4090 24G（约 1.9 元/时）。充 10 元够把这一课来回跑好几遍。
#动作做到什么算成
1手机号注册进 autodl.com，右上角注册，手机号收验证码，登录进控制台
2实名认证个人中心传身份证实名；是学生走「学生认证」有折扣（可选）
3充值最小额度「充值」充 10 元——按量计费，用多少扣多少，不用先充大额
4租一张 4090控制台「租用新实例」：计费按量、地区选近的、GPU 选 RTX 4090 24G、数量 1

价格会随供需浮动，4090 现价约 1.9 元/时，下单前看平台实时页。这课 500 条在 4090 上十几分钟训完，烧不了几毛钱。

充值 ≠ 租卡。充值是往账户存钱，租卡是创建实例开始计费。只充值不租卡不会扣钱；实例显示「运行中」才开始按秒计费，用完记得关机停费。
这一章钉住了三件事
  • 钉住了：注册 → 实名 → 充 10 元 → 租 4090，四步走完
  • 不这么做会：误以为充值完就能用，或者租了高配卡烧钱
  • 下次遇到同类问题，先看：实例状态是不是「运行中」、计费方式是按量还是包月
带走只充 10 元、只租 4090——「运行中」才计费，用完就关机。

3开机选镜像：选现成的 LLaMA-Factory

结论镜像选社区里现成的 LLaMA-Factory，省掉装环境那两小时；配环境、传数据用「无卡模式」，不烧 GPU 钱。

选镜像，两分钟的事

路怎么做什么时候用
社区镜像租卡页点「社区镜像」，搜 LLaMA-Factory，选带 torch + CUDA 的版本本课主线，环境已装好，开箱即用
base 镜像自装选 PyTorch 2.x + CUDA 12.x 的 base，再 git clone + pip install -e ".[torch,metrics]"想要完全干净的版本控制

盘的分工，先记死

盘路径放什么
系统盘/root代码、小文件。空间小，别放大模型
数据盘/root/autodl-tmp模型权重、训练产物、要留的数据

关机保留磁盘数据，但「释放实例」会清空；连续关机 15 天也会被释放。权重和产物一律放 /root/autodl-tmp，别放系统盘。

开机第一件事：验证三行

python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
nvidia-smi
ls /root/autodl-tmp
2.x.0+cu12x True
NVIDIA GeForce RTX 4090 ... 24GB

第一行 True、第二行认出 4090、第三行数据盘在，环境就绪。装 Unsloth 一条命令：

pip install unsloth
Unsloth 装不上，别硬修。它对 transformers 版本有要求，偶尔和镜像里已装的版本冲突。装不上就把 yaml 里的 use_unsloth: true 删掉，退回普通 QLoRA 照样能训——Unsloth 是加速，不是必须。
「无卡模式」省钱的正确姿势：配环境、传数据、写 yaml 这些不碰 GPU 的活，用无卡模式开机（约 0.1 元/时）；真正训练前再关机、换带卡模式重启。光配环境就用带卡机，能白烧掉几块钱。
这一章钉住了三件事
  • 钉住了：镜像选现成的 LLaMA-Factory；模型和产物放 /root/autodl-tmp
  • 不这么做会：模型放系统盘，下到一半磁盘满；配环境用带卡机，白烧钱
  • 下次遇到同类问题，先看：盘分对没、Unsloth 装不装得上、无卡模式开没开
带走镜像选现成、数据放数据盘、配环境用无卡——三条都是省钱，不是省事。

4准备数据：alpaca 格式 + 注册进 dataset_info

结论LLaMA-Factory 吃 alpaca 格式（instruction/output），和 L04 的 query/response 不是一回事；而且要写进 dataset_info.json 它才认。

数据长什么样（和 L04 对比）

# L04 ms-swift 吃的：query / response
{"query": "请根据用户法律问题生成一段…用户问题：老板让我天天加班不给钱怎么办", "response": "《劳动法》第四十一条…百分之一百五十…"}

# L05 LLaMA-Factory 吃的：instruction / output
{"instruction": "请根据用户法律问题生成一段…用户问题：老板让我天天加班不给钱怎么办", "output": "《劳动法》第四十一条…百分之一百五十…"}

字段名从 query/response 换成 instruction/output，内容一字不动。本课附件 demo_hyde_500_alpaca.jsonl 已转好，直接上传。

上传 + 注册，两步

#动作怎么做
1上传数据JupyterLab 把 demo_hyde_500_alpaca.jsonl 拖进 /root/autodl-tmp/LLaMA-Factory/data/
2注册进配置编辑 data/dataset_info.json，加一个键，指向这份文件
在 data/dataset_info.json 里，最后一个键后面加：
"hyde_demo": {
  "file_name": "demo_hyde_500_alpaca.jsonl"
}

键名 hyde_demo 就是后面 yaml 里 dataset 要填的名字。没注册，框架找不到这份数据，训练集就是空的。

# 传完验一眼：行数、字段名
wc -l /root/autodl-tmp/LLaMA-Factory/data/demo_hyde_500_alpaca.jsonl
head -n 1 /root/autodl-tmp/LLaMA-Factory/data/demo_hyde_500_alpaca.jsonl
500 .../demo_hyde_500_alpaca.jsonl
{"instruction": "…", "output": "…"}
手上只有 L04 那份 query/response？不用手动改，一条 python 转：{"instruction": r["query"], "output": r["response"]}。记住这条判据就够了：字段名是框架定的，不是数据定的——换框架，先问它吃哪种格式。
这一章钉住了三件事
  • 钉住了：LLaMA-Factory 吃 instruction/output，且要在 dataset_info.json 注册
  • 不这么做会：直接丢 query/response 进去，或漏了注册，训练集是空的
  • 下次遇到同类问题，先 head 看字段名、再看 dataset_info 里注册没注册
带走换框架先问一句「你吃哪种格式」——LLaMA-Factory 的答案是：alpaca + 注册。

5一条命令起训：一个 yaml + QLoRA + Unsloth

结论起训 = 一个 yaml 配置文件 + 一条 llamafactory-cli train。QLoRA 两条参数、Unsloth 一条开关，其余照抄。
把下面存成 hyde_qlora.yaml，放在 LLaMA-Factory 目录下：
### model
model_name_or_path: Qwen/Qwen3-1.7B
trust_remote_code: true

### method
stage: sft
do_train: true
finetuning_type: lora
lora_rank: 16
lora_alpha: 32
lora_target: all

### dataset
dataset: hyde_demo
template: qwen3
cutoff_len: 1024

### output
output_dir: /root/autodl-tmp/saves/qwen3-1.7b/hyde
logging_steps: 10
save_steps: 50
plot_loss: true

### train
per_device_train_batch_size: 2
gradient_accumulation_steps: 8
learning_rate: 1.0e-4
num_train_epochs: 3.0
lr_scheduler_type: cosine
warmup_ratio: 0.05
bf16: true

### QLoRA 量化（两条一起才叫 QLoRA）
quantization_bit: 4
quantization_method: bnb

### 加速
use_unsloth: true
# 一条命令起训
llamafactory-cli train hyde_qlora.yaml
首次跑会自动下 Qwen3-1.7B（约 3GB），国内走 HF 很慢甚至断。起训前先设下载源，二选一：export HF_ENDPOINT=https://hf-mirror.com（走镜像），或 export USE_MODELSCOPE_HUB=1（让 LLaMA-Factory 从魔搭下）。这一步不是卡死，是它在拉模型。

关键参数逐个过

参数这一课填什么为什么
model_name_or_pathQwen/Qwen3-1.7B基座模型，会自动下载（记得先设下载源）
finetuning_typelora只训补丁，不训整个模型
quantization_bit + method4 + bnb两条合起来才是 QLoRA，基座压到 4bit 省显存
datasethyde_demo就是第 4 章注册的那个键名
templateqwen3对话模板要跟模型家族对上，Qwen3 用 qwen3
output_dir数据盘下 savescheckpoint 落数据盘，关机不丢
use_unslothtrue加速开关，装不上就删掉这一行
learning_rate1e-4LoRA 常用档，比全参大一个量级
起训前自检三句。① nvidia-smi 认到 4090；② wc -l 是 500 且字段是 instruction/output；③ yaml 里 output_dir 在 /root/autodl-tmp 下。三句都过，回车。
这一章钉住了三件事
  • 钉住了：QLoRA = quantization_bit: 4 + quantization_method: bnb，加速 = use_unsloth: true
  • 不这么做会：漏了量化两条退回普通 LoRA 多占显存；忘了设下载源，卡在拉模型
  • 下次遇到同类问题，先看：模型下下来没、dataset 键名对不对、output_dir 在不在数据盘
带走L04 一条命令、L05 一个 yaml——QLoRA 那两条参数（bit + method）到哪都不能少。

6看 loss、拿 adapter

结论loss 一路往下、落到个位数，saves/ 目录冒出 checkpoint，就算训成。adapter 还是那个几十 MB 的补丁，不是整个模型。

日志怎么读

{'loss': 2.68, 'grad_norm': 1.12, 'learning_rate': 1.9e-05, 'epoch': 0.17}
{'loss': 1.91, 'grad_norm': 0.98, 'learning_rate': 4.2e-05, 'epoch': 0.33}
{'loss': 1.38, 'grad_norm': 0.81, 'learning_rate': 5.3e-05, 'epoch': 0.50}
{'loss': 1.12, 'grad_norm': 0.70, 'learning_rate': 6.1e-05, 'epoch': 0.67}

和 L04 一样只看一件事：loss 是不是一路往下。趋势必须往下、不再反弹，落到个位数（2 以下更稳）就算学到。

saves 目录里有什么

/root/autodl-tmp/saves/qwen3-1.7b/hyde/
├── checkpoint-50/              # 每 50 步存一个点
│   ├── adapter_config.json     # LoRA 配置
│   └── adapter_model.safetensors  # 补丁权重，几十 MB
├── checkpoint-100/
└── training_log.jsonl          # 完整 loss 记录

adapter_model.safetensors 就是这一课的成果，几十 MB。基座 3GB 不用下，adapter 要配着基座才能用。

断了怎么办：在 yaml 里加 resume_from_checkpoint: saves/qwen3-1.7b/hyde/checkpoint-50 再跑，会从那个点接着训，不是从头再来。
这一章钉住了三件事
  • 钉住了：看 loss 只看趋势；成果是 adapter 那个几十 MB 的补丁文件
  • 不这么做会：盯着 loss 绝对值较劲，或者把整个 3GB 模型当下载目标
  • 下次遇到同类问题，先看：loss 趋势、checkpoint 目录在不在数据盘
带走loss 看趋势不看绝对值，成果是几十 MB 的 adapter——这条和 L04 一字不差。

7验它学会了

结论训完用 llamafactory-cli chat 喂一条口语问题，看它吐不吐法条语体——吐得出来才算学会，吐不出，这一课没交账。
llamafactory-cli chat \
  --model_name_or_path Qwen/Qwen3-1.7B \
  --adapter_name_or_path /root/autodl-tmp/saves/qwen3-1.7b/hyde/checkpoint-150 \
  --template qwen3 \
  --infer_backend huggingface

前后一对比，效果就出来了

时机输入一句口语输出应该长这样
训练前老板让我天天加班不给钱，怎么办答非所问，或直接给建议（改写器不该做这个）
训练后老板让我天天加班不给钱，怎么办一段带「延长工作时间」「百分之一百五十工资报酬」的法条语体文本
判断它学会的硬标准：喂口语，输出是「一段可以拿去检索的书面文本」，不是「给你的建议」。输出带法条号、法律概念、责任类型，就对了。

把 adapter 下载到本地

# 在终端打包，再从 JupyterLab 文件树右键下载；别下整个 3GB 模型
cd /root/autodl-tmp/saves/qwen3-1.7b/hyde
tar -czf hyde_adapter.tar.gz checkpoint-150/

打出来的 hyde_adapter.tar.gz 几十 MB，下载秒完。到这里，整条链在 AutoDL 上走通了。

这一章钉住了三件事
  • 钉住了：验证就是喂口语、看输出，是不是变成了法条语体
  • 不这么做会：不验就打包，结果训歪了都不知道
  • 下次遇到同类问题，先喂一条最土的口语，看输出像不像法条
带走别急着庆祝，先喂一句口语——输出变成法条语体，才叫学会。

8小结

结论这一课交出去的是「同一份任务、换一套跑法」：L04 魔搭免费卡试通，L05 AutoDL 正式卡 + LLaMA-Factory 复现。平台和框架换了，任务和数据没换。

三条边界，越界就返工

  • 模型和产物永远放数据盘。放系统盘，不是磁盘满就是关机后要重下。
  • 配环境用无卡模式。带卡配环境，钱白烧。
  • 数据不注册就不算数。忘了写 dataset_info.json，训练集是空的，训了个寂寞。

这门课留下的判据
  • 判据一：换平台先认三样——命令入口、数据格式、下载源，认不清就搬不过去

  • 判据三：Unsloth 是加速不是必须，装不上就删，别在环境上硬修半天
带走魔搭是「试通」，AutoDL 是「正式」——两条链跑通后，你能在两套框架之间随意切换，这才是这一课的底子。
